# 03 · 案例：EU4「随机名字权重失效」的根因与修复

> 目标：`eu4.exe` v1.37.5.0（Inca），`ImageBase 0x140000000`。全部地址为 **RVA**。
> 这是本套文档里**最适合作为"逆向驱动修复"教学案例**的一篇：
> 症状很模糊（"某些名字出现得异常频繁"），修复只有三处、共 **16 个字节**，
> 但根因的确认走了**五层证据**，并且最终在**算法层**闭环。
>
> 玩家侧描述：原版游戏按权重随机挑名字时，**大约一半的情况下会直接取列表中的第一个名字**，
> 权重设置形同虚设。

---

## 1. 症状与第一反应（为什么不能直接改）

**症状**：加权名字表（脚本 `monarch_names = { "Karl" 10 "Heinrich" 3 … }`）里，
排在**第一号位**的名字出现频率明显异常；越靠后越罕见。

**第一反应**（错误方向）：以为权重解析有问题 ⇒ 去找 `AddEntry` 里读权重的代码。

**为什么这个方向会走错**：整函数级还原 证明
**建表完全正确**（见 §5）。问题不在"权重怎么读进来"，而在"**怎么用这个权重去选**"。

⇒ **教训**：症状指向"数据被读错"时，要先确认**数据本身是否正确**，
再决定是查"读入端"还是"使用端"。

---

## 2. 病根：有符号取模 + 完整 32 位随机源

### 2.1 三处宿主

| 站点 | RVA | cover | 回跳 | 宿主函数 | 覆盖的指令 |
|---|---|---|---|---|---|
| **P1** | `0xDA989B` | 5 | `0xDA98A0` | `WeightedNameList_PickByRandomIndex`（`0xDA9880`） | `mov rdi,r8` / `mov esi,edx` |
| **P2** | `0x280274` | 6 | `0x28027A` | `PickNameFromCultureLists`（`0x2801F0`） | `mov eax,edi` / `cdq` / **`idiv r8d`** |
| **P3** | `0xDA9A82` | 6 | `0xDA9A88` | `WeightedNameList_GetByModIndex`（`0xDA9A60`） | `mov eax,edx` / `cdq` / **`idiv r8d`** |

三处的共同形态：

```asm
mov  eax, <随机值>     ; 或索引
cdq                    ; ★ 符号扩展 —— 这是"有符号"的铁证
idiv ecx               ; ★ 有符号除法 ⇒ 余数可为负
```

### 2.2 为什么负余数必然导致"总选第一个"

加权表的扫描是「**累减权重，减到负即命中**」：

```c
v11 = rnd % 权重和;                  // rnd < 0 ⇒ v11 为【负】
for (i = 0; ; ++i) {
    if (条目属于本组) { v11 -= 条目权重; if (v11 < 0) break; }
    ...
}
return 条目;
```

**负的被除数 ⇒ 负的余数 ⇒ 循环第一步减完权重后仍为负 ⇒ 立刻 `break`，返回该组第一个条目。**

而输入是 `Random_GetGlobalMT()` 的**完整 32 位**，符号位为 1 的概率**恰为 50%**
⇒ **约一半的取名直接落在名字表第一行** —— 与症状完全吻合 ✓

### 2.3 三处的后果**并不相同**（容易漏看的一点）

| 站点 | 模数语义 | 负余数的实际后果 | 严重度 |
|---|---|---|---|
| **P1** | 权重和 | 累减立刻 `< 0` ⇒ **总选中第 0 个可用项** | 症状可见（"某些名字异常频繁"） |
| **P2** | `total` | 负余数被调用方当**无符号**用 ⇒ `begin + 32 × 巨值` = **野指针** | ★ **潜在崩溃** |
| **P3** | **条目数**（不是权重和） | `begin + 40 × 负` = **数组之前的 OOB** | ★ **潜伏型越界** |

> ★ **关键观察**：P1 是"看得见的功能缺陷"，P2/P3 是"看不见的内存安全缺陷"。
> **只修 P1 会让症状消失，但把两个越界留在那里。**
> 这正是本项目 2026-10-05 那次重写漏掉 P1/P2/P3 后、
> 又在补回时被明确要求**三个一起修**的原因。

**P1 的 mode 1 尤其严重**：它的模数是「总权重 − 男性权重和」。
**mode 2 更糟** —— 被除数先做 `1000 * rnd`，**32 位内即溢出**，符号完全不可控。

---

## 3. 随机源与 mode：从一个函数钉死

`Heir_InitNewHeir`（`0xA55CF0`，**1885 B / 475 条指令 / 30 处 call**）是继承人的取名编排者。
它把 P1 的**两个前提**都定死了：

| 前提 | 值 | 依据 |
|---|---|---|
| **随机源** | `random = Random_GetGlobalMT(heir.cpp, 0x142)` 的**完整 32 位**（可为负），**直接作为被除数**传给 `WeightedNameList_PickByRandomIndex` | 逐指令 |
| **mode 来源** | **`mode = flag4 ? 0 : (a5 ? 1 : 2)`**（函数第 4 / 5 参数） | 逐指令 |
| **出参 `a8` 的角色** | **性别**（= 命中元素的 `flag`，或回退时的概率判定结果） | 逐指令 |

⇒ **同一个 `random` 被 mode 0/1/2 三个分支共用**
⇒ 补丁"在重放 `mov rdi,r8` / `mov esi,edx` **之前**掩 `rdx`"这一处改动
**一次覆盖三分支** ✓

### 3.1 三个 mode 的差别

| mode | 含义 |
|---|---|
| 0 | 取 `flag` 为**假**的条目（男性），权重 = `total_a` |
| 1 | 取 `flag` 为**真**的条目（女性），权重 = `total_a − total_b`（总权重 − 男性权重和） |
| 2 | **双权重 ×1000** |

---

## 4. 修法：把进入除法的值掩成非负，除法仍交给桩

### 4.1 三处分别怎么做

| 站点 | 被除数来源 | 桩里做什么 | 为什么够 |
|---|---|---|---|
| **P1** | `edx`（`Random_GetGlobalMT()` 完整 32 位） | 掩 `rdx & 0x1FFFFF`，再重放 `mov rdi,r8` / `mov esi,edx` | ★ 掩码放在两条重放**之前**，`esi` 由 `mov esi,edx` **自然取到同一个非负值** ⇒ **不需要单独掩 `esi`**，两条路径（mode 0/2 用 `esi`、mode 1 用 `edx`）**一起被覆盖** |
| **P2** | `edi`（第 1 参数） | 掩 `rax` + **清 `rdx`**，把 `cdq; idiv` 换成无符号 `div r8d` | 余数仍在 `rdx`，与紧随其后的 `cmp ecx,edx` 对齐 |
| **P3** | `edx`（第 2 参数） | 同上 | 同上 |

### 4.2 为什么掩 21 位（`MASK_BITS = 21`，`MASK_VALUE = 0x001FFFFF`）

1. 保证**非负** ⇒ 余数必为正；
2. 把值限制在 **2²¹** 以内 ⇒ **mode 2 的 `1000 * rnd` 不再 32 位溢出**；
3. **余数仍然均匀** —— 偏差 < `权重和 / 2²¹`。

> 第 2 条是最容易漏掉的约束：单看"让它非负"用 31 位掩码也够，
> 但那样 mode 2 的 `1000 × rnd` 会在 32 位里溢出，**符号又不可控**。
> ⇒ **掩码宽度必须同时满足"非负"和"下游乘法不溢出"两个条件。**

### 4.3 为什么除法指令本身留在汇编桩里、不用 C 的 `/` 表达

**`div` 的溢出行为（商放不下 32 位时抛 `#DE`）必须与硬件一致**，C 的 `/` 表达不了。

⇒ 分工原则：

| 操作类型 | 放在哪 |
|---|---|
| **纯数据操作**（掩码、清零） | **C++ handler** 里改 `reg_pack` |
| **除法指令**（`div r8d`） | **留在桩里重放** |

---

## 5. 算法级闭环：为什么"只掩被除数"是**既必要又充分**

跨了三次还原才闭环，过程本身就是方法论的示范。

### 5.1 第一步：宿主函数还原 ⇒ 必要性成立

整函数级还原（`GetByModIndex` 52 B / `PickByRandomIndex` 472 B，**都是叶子**）
与 整函数级还原（`PickNameFromCultureLists` 327 B / `PickNameFromCulture` 73 B）
把三个站点所在的函数整函数还原 ⇒ 取模修复从**指令级**升到**算法级**。

| 站点 | 病根（算法级） | 判定 |
|---|---|---|
| **P1** | 三个分支都是 `random % 权重量`（**有符号**）⇒ 负余数 ⇒ 累减立刻 `< 0` ⇒ **总选中第 0 个可用项** | ✅ |
| **P2** | `index % total` 的负余数被当**无符号**用 ⇒ `begin + 32 × 巨值` = **野指针** | ✅ |
| **P3** | `index % count` 负余数 ⇒ `begin + 40 × 负` = **数组之前的 OOB** | ✅ |

**顺带查实的容器布局**：

```
WeightedNameList 元素 = 40 字节
    +0x00  名字 CString（32 字节）
    +0x20  int32 weight
    +0x24  uint8 flag        （1 = 女性）

表头 56 字节：
    +0x10  总权重和
    +0x14  男组权重和
    +0x18/+0x20/+0x28  begin/end/cap
    +0x30  女性【条目计数】
```

★ **文化名字表为空时的兜底名是静态 `CString`：`"Adam"`（男，`0x142326F70`）/ `"Eve"`（女，`0x142326F50`）。**
（⇒ 如果你在实机里看到 Adam/Eve，那不是数据错误，是**空表回退**。）

### 5.2 第二步：编排者还原 ⇒ 前提实证

`Heir_InitNewHeir` 还原后（见 §3），**随机源与 mode 都定死了** ⇒ P1 的两个前提得证。

**此时残留的唯一前提**【推定】：除数必须 ≥ 0 —— 它们是权重累加量、为 0 时有 `if` 挡住；
但**建表方尚未还原，故未证**。

### 5.3 第三步：建表方还原 ⇒ **残留风险关闭**

`WeightedNameList_AddEntry`（`0xDA9AA0`，**460 B / 124 条指令 / 10 处 call**）：

```c
name   = LookupLocalizedString(src->nameKey)      // src + 0x34；走本地化链 ✓
w      = atoi(src->weightText)                    // src + 0x444（十进制字符串）
weight = abs(w)                                   // ★ 元素权重恒 ≥ 0
flag   = (w < 0) ? 1 : 0                          // ★★ 负权重 ⇒ 女性
```

★ **三个统计量只增不减 ⇒ 除数恒 ≥ 0。**

⇒ `PickByRandomIndex` **三个分支的除数全部恒 ≥ 0**
（`total_b`、`total_a − total_b` = 女性权重和、mode 2 加权和）。

⇒ **补丁 P1「在重放两条 `mov` 之前掩 `rdx`」既必要又充分**：
**被除数非负 + 除数非负 ⇒ 有符号除法余数不为负**，"总选中第 0 个可用项"的症状被根除。

> ★ **这就是"算法级闭环"的样子**：不是"改完症状轻了"，
> 而是**从数据产生（`AddEntry`）到使用（`PickByRandomIndex`）的每一环都能证明符号非负**。

### 5.4 一条对 mod 作者**直接有用**的结论

**`monarch_names` 里的权重写成负数 = 该名字归入女性池。**

```c
monarch_names = {
    "Karl"    10
    "Heinrich" 3
    "Maria"   -8      # ★ 负权重 ⇒ flag = 1 ⇒ 女性
}
```

引擎取 `abs(负值)` 当权重、同时把 `flag` 置 1。
⇒ 如果你希望某个名字**只给女性**，写负数即可，不必另开一张表。

## 7. 这个案例里能带走的五条经验

1. **症状"权重不起作用"≠ 权重被读错。** 先用建表方证明数据正确，再怀疑使用端。
2. **一处根因可以有三处站点，后果各不相同。** P1 是功能缺陷，P2/P3 是内存安全缺陷。
   **只修症状最明显的那个，等于把越界留在原地。**
3. **掩码宽度不是随便选的。** 必须同时满足"非负"与"下游乘法不溢出"。
4. **`div` 的溢出语义必须由硬件负责。** 涉及除法时，纯数据操作与指令重放要分开。
5. **"必要性"和"充分性"是两件事，要分别取证。**
   拿到"改了以后症状消失"只到必要性；充分性要追到**数据产生端**（`AddEntry`）。
