# 01 · 目标二进制、地址换算与全套方法学

> 本文是整套文档的**基线**。任何一篇里的 RVA 要能对上号，都依赖本文的这几条约定。
> 目标：`eu4.exe` v1.37.5.0「Inca」，`ImageBase 0x140000000`。
> 全部结论的证据等级沿用项目约定（见 §5）。

## 1. 目标指纹：先对指纹，再动一个字节

逆向与打补丁的第一原则是**版本可判**。本项目在补丁入口处做硬校验，**指纹不符则一个字节都不改**。

| 项 | 值 |
|---|---|
| 文件 | `eu4.exe`（EU4 v1.37.5.0「Inca」，64 位） |
| 大小 | **38,462,504** 字节 |
| 格式 | PE32+ x64 |
| `ImageBase` | **`0x140000000`** |
| `SizeOfImage` | **`0x025E0000`** |
| `TimeDateStamp` | **`1727949497`** |
| SHA-256（截断） | `9AD3EFE1…771A` |
| SHA-256（完整） | `9AD3EFE1AF169F40EE577F9DAE5DEBBC87AF6FB8B5450FB345EBF110DC4D771A` |
| MD5 | `5af10c50faebd12408149a3a27deffcb` |
| `machine` | `0x8664`（x64） |
| 构建 | 分支 `release_1.37.5`，修订 `835bfdf8ca24c291a1b3f1b5bc72d47e7df1ae18`（2024-10-03），Steam appid `236850` / buildid `15918133` |
| PDB | **无** |
| 签名 | 有效（Paradox Interactive AB (publ)） |
| `.text` 范围 | `0x140001000..0x141B66000` = **28,725,248 字节** |

**IDB 规模**（供对照你自己的工作）：`83,419` 个函数（905 命名 / 2,501 库 / **80,013 未命名 = 95.9%**）、`53,668` 个字符串。

> ⚠️ **1.37.5 是 64 位**。网上大量基于 **32 位旧版**的偏移表与注入方案
> **全部作废** —— 这是本领域最容易踩的"版本陷阱"。

**为什么三个指纹都要**：

- `SizeOfImage` + `TimeDateStamp` 足以挡住绝大多数版本混用（Steam 的公开 beta 分支各自不同）；
- 但**同一版本重新打包**可能保持这两个值而内容不同 ⇒ 对**逐字节**场景（写死字节模式、跨版本断言）必须再比 SHA-256。

**⭐ 一条可以直接复用的实测结论**：第三方项目 `EU4-Menu-Patch` / `EU4-Unicode-Patch`
（作者 VulonLok，均 MIT）硬编码的 `eu4.exe` SHA-256 截断值同样是 `9AD3EFE1…771A`，
**与本工程的 `binaries\eu4.exe` 逐字节相同**。

⇒ 这意味着：

1. 他们的 RVA **就是**我们的 RVA，**不存在版本换算问题**，可以逐条吸收；
2. 更强的验证途径：Unicode-Patch 自带 **202 条「改前字节」断言**，
   在本工程 IDB 中逐条比对，**202/202 命中** —— 这等于一份第三方交叉校验过的地址表。

> ⚠️ 反过来说：**如果你的目标 exe 指纹不符，本文所有 RVA 都不可直接使用**，
> 必须走 §3.3 的「模式 + RVA 双判据」重新定位。

### 1.1 ⚠️ 基线必须是未被修改的原版可执行文件

校验补丁站点时，**不要把任何被第三方修改过的 exe 当基线** —— 即便它的文件尺寸与正版
完全相同，其字节内容与函数布局都可能已被改动，据此得出的站点与签名会全部失效。

判据只有一个：**PE 头里的指纹**（`SizeOfImage` / `TimeDateStamp`，必要时再加代码段
的 SHA-256 截断值）与本工程记录一致。指纹不符 ⇔ 不是同一个二进制，直接放弃校验。
## 2. 地址换算：三套地址，别混

这是最容易出错、也最容易被后来者踩的地方。

```
objdump / 反汇编器里看到的完整地址  =  ImageBase + RVA
    0x140313F40                     =  0x140000000 + 0x313F40

运行时地址（调试器看到的）           =  实际模块基址 + RVA
    基址见 MonarchNameFix.log 的 PROBE 行（ASLR 会变）

IDA 里（本 IDB 已设 ImageBase）      =  与 objdump 一致，即 0x140xxxxxx 形式
```

**约定**：本套文档**一律写 RVA**（`0x313F40` 形式），因为它与 ASLR 无关、可跨进程复用。
只有在必须与调试器现场对照时才写运行时地址。

**换算脚本**（PowerShell）：

```powershell
# 运行时地址 → RVA
$rva = 0x00007FF6_313F40 - 0x00007FF6_000000   # 基址从日志/调试器取
'{0:X}' -f $rva
```

## 3. 整套方法学

### 3.1 五层证据链：一个结论要过五关

补丁的一个站点最终被接受，要同时满足下面五层。这套结构**同样适用于判断"别人的补丁站点对不对"**。

| 层 | 检查什么 | 手段 |
|---|---|---|
| ① **字节** | 站点处的原始字节与模式逐字节相符，`cover` 长度正确覆盖**完整指令** | `scripts/verify_patch_targets.py` |
| ② **回跳** | `resume = site + cover`，且落点是一条**完整指令的边界**（不能落在指令中间） | 同上 |
| ③ **调用链** | 宿主函数是谁、调用者是谁、该站点在控制流里的位置（进入/循环前/调用前/调用后/出口） | IDA xref + 整函数还原 |
| ④ **字段** | 站点处各寄存器指向什么对象、访问的偏移属于哪个类（用 vtable + 对象大小双重确认） | 逐指令 + `static_assert` |
| ⑤ **算法** | 站点试图改变的行为，其**算法语义**能从整函数还原中推出来 | 整函数级还原的 C++ 文件 |

> ★ **本项目 9 个站点 9/9 通过这五层**，明细见 工程内部记录。
> ★ 第 ⑤ 层是关键分野：只过①~④ 是"位置对得上"，过了⑤ 才是"**改了以后语义确实正确**"。

### 3.2 命名要有门槛：证据等级 E1/E2/E3

游戏没有符号表。**给函数起错名字比留着 `sub_` 更有害** —— `sub_` 至少不骗人。

| 等级 | 判据 | 能否改名 |
|---|---|---|
| **E1** | 日志字符串含 `file.cpp:line`；RTTI / vtable 匹配；字符串或数据文件直接对应 | ✅ 可命名 |
| **E2** | 调用者/被调用者语义收敛；多处交叉引用一致；数据结构布局自洽 | ✅ 可命名（注释标 E2） |
| **E3** | 仅凭代码形态推测 | ❌ **只写注释，不改名** |

**⭐ 一条代价换来的教训**：项目早期曾把"继承人随机姓名"的来源判成文化的 `male_names`，
实际是 `common/countries/*.txt` 的 `monarch_names` —— 当时只有 E3 级证据却当 E1 用了。
**所以"证据等级"和"改名门槛"必须写进规范、写在注释里。**

判决语境里还常用一套双记号（整函数级还原 目录）：

| 标记 | 含义 |
|---|---|
| **【确证】** | 依据充分、逐条对应反汇编，行为可判定等价 |
| **【推定】** | 依据较充分但非唯一解释；**必须写明推理链** |
| **【未知】** | 依据不足；只描述"它做了什么"，**用原地址占位，不臆造原型** |

**两条红线**：

- **IDA 的反编译不是终点**。它会隐藏 SEH、把位运算简化掉、把 `imul` 魔数写成漂亮除法。
  凡是要写进 C++ 的结论，都**回到字节级确认**。
- **不为了"能跑"而简化**。读不懂就标【未知】并保留原地址。

### 3.3 定位：字节模式 + RVA 双判据

**单靠字节模式必错，单靠 RVA 则不能跨版本。**

| 判据 | 职责 |
|---|---|
| **字节模式**（19~37 字节） | 负责"**跨版本仍找得到**" |
| **RVA** | 负责"**多个候选中确定是哪一个**" |

规则：

1. 命中**恰好 1 次** ⇒ 直接采用；
2. 命中**多次** ⇒ 在命中集合里挑 `RVA == site_rva` 的那个（**RVA 是权威判据**）；
3. 命中**0 次** ⇒ **报错，不猜**。

**⭐ 模式必须够长 —— 这是血泪教训**：

第一版只用 5~8 字节。结果 `48 89 5C 24 08` 在 `.text` 里命中 **15437 次**，
6 个钩子只装上 1 个，表现为"姓被追加了却没人重排"、**名字全乱**。

更隐蔽的一例：某次安装实际落在 `0x1c605d` 而不是期望的 `0x3142f2` ——
模式匹配到了别的地方，而且**装上了、没报错**。

⇒ 现在的做法：模式取 **16~37 字节**，且安装前**逐字节比对**；
`install.cpp::kSites[]` 每条都带 `site_bytes`，对不上就**拒绝安装**，
而不是"取签名第一个命中"。

**★ 实测命中计数**（这批站点的真实数据，可作为"你的模式够不够长"的参照）：

| 站点 | 模式长度 | `.text` 内命中次数 |
|---|---|---|
| P1 / P2 | 16 B | 1 |
| P3 | 18 B | 1 |
| **P6** | **37 B** | **4** ← 编译器标准模板，必须靠 RVA 筛 |
| P7 | 19 B | 1 |
| P10 | 23 B（跨 `call` 的 `rel32` 用 `?`） | 1 |
| P11 | 21 B | 1 |
| **P4** | **36 B** | 1，但**命中点不是站点**（`pattern_to_site = 0x1E`） |
| P8 | 20 B | 1 |

⇒ 两条判据分得很清楚：

1. **命中 4 次是正常的**（编译器会为不同函数生成同样的序言）⇒ **必须靠 RVA 筛选**；
2. **命中 1 次也可能是"命中点 ≠ 站点"** ⇒ 必须用 `pattern_to_site` 显式表达偏移。

**为什么 P6 必须配合 RVA**：`BuildFullName_Impl` 的序言是编译器通用模板，
在 `.text` 里有 **4 份完全相同的拷贝**，**单靠模式永远不唯一**。

**`?` 通配是必须的**：P10 的模式跨过一条 `call`，其 `rel32` 会随版本变
⇒ 用 `? ? ? ?` 通配掉，只保留稳定的前后字节。

## 4. ⚠️ 事故：`VirtualProtect` 影响整页

这一条值得单独成节，因为它造成的症状**极具误导性**。

**现场**：写完 P1 的站点后，把**同一个页面**设回 `RX`；随后再写 P2（落在同一页）
⇒ 访问违例 ⇒ **异常逃出 `DllMain`** ⇒ **加载器静默判定 DLL 加载失败**
（**无弹窗、无日志**）。

**症状**：**游戏正常启动 + 部分补丁生效 + 日志被截断。**

⇒ 排查时会以为"补丁基本能用，只是日志有点问题"，而实际上
**DLL 已经加载失败了**，且**游戏内存已被改了一半**。

**正解：两阶段安装** ——

```
① 全部写桩（把所有要改的字节一次写完）
② 一次性改页保护 + FlushInstructionCache
③ 才去改站点
```

⇒ 这条已经写成回归用例：`[regress] write to same page after VirtualProtect(RX): FAULT`。

**★ 更一般的原则**：**静默失败比崩溃更贵**。
现在三阶段都包 `__try/__except`，异常时写 `[!] unexpected exception, code=0x…`。

> ★ 另一条同源教训：**日志格式化的缺陷会误导排查**。
> 曾经有 `cave=0xffff0000` 这样的日志，实际是 `cave − mod` 被按 `uint32` 打印
> （cave 在基址下方 64 KB）⇒ 看着像野指针，其实一切正常。
> **日志里的每个值都要能对上它的类型。**

## 4. 用 `.pdata` 拿函数边界，不要靠 `call` 目标猜

PE 的异常目录（`DIRECTORY_ENTRY_EXCEPTION` / `RUNTIME_FUNCTION` 数组）给出了
**编译器自己记录的每个函数起止**。

- 「某个 RVA 属于哪个函数」⇒ 变成一次 **`bisect`**；
- 比"靠 `call` 目标反推"可靠得多，也不受内联/尾调用影响。

本项目所有"函数边界"类结论都取自 `.pdata`，例如：
`CMonarch_GetFullName` 的 `0xA4B2C0..0xA4B5B0`、**752 B / 182 条指令 / 24 处 call**。

**从第三方工具借来的三条**（`pefile` + `capstone` 把整个 `.text` 索引进 SQLite）：

```sql
refs(src, dst, kind, asm)   -- RIP 相对引用 + 相对 call/jmp
strings(rva, value)         -- 只扫【非可执行段】，≥4 可打印字符 + NUL 结尾
functions(start, end)       -- 用 .pdata 拿函数边界
imports(rva, name)          -- "dll!func"
```

三个可照搬的点：

1. **`refs` 表建 `dst` 索引** ⇒ "谁引用了这个字符串/这个全局"一次查询；
2. **`strings` 只扫非可执行段，且要求 NUL 结尾** ⇒ 免掉大量误报；
3. 函数边界用 `.pdata`（见上）。

> 有 IDA 时不必重写（`idautils.XrefsTo` / `Strings()` 已经能做），
> **缺的是"把结论落成表"** —— 静态索引的价值在可复现查询。

### 3.5 整函数还原：把"看懂个大概"变成"能写出来"

项目把 EU4 的函数用 C++ **整函数**重写一遍存进 整函数级还原（一函数一文件）。

**为什么值得单独留存**：

1. **补丁会变，游戏逻辑不会。** 钩子怎么挂是实现细节；函数在做什么是事实。
   将来换实现、换版本，这份还原仍是对 v1.37.5.0 行为的记录。
2. **它是可审查的。** 汇编只能读，C++ 可以讨论、可以改错、可以对照。
3. **它逼出真正的理解。** **写不出来的地方，就是还没读懂的地方** ——
   这比"看懂个大概就去改 5 字节"可靠得多。

**每个还原文件必须写全**：

1. **还原对象**：RVA 范围、字节数、指令数、来源版本（ImageBase / SizeOfImage / TimeDateStamp）
2. **函数原型**：每个参数的寄存器归属、返回值
3. **数据结构**：读出的偏移与布局，集中放 `game_types.hpp`，附 `static_assert` 校验
4. **变量表**：反汇编里的寄存器/栈槽 → C++ 里的变量（类型、含义、依据的 RVA）
5. **被调函数**：地址 + 从调用点反推的原型 + 置信度（**本轮只声明，不还原**）
6. **全局对象**：RIP 相对取址的地址，用 `static constexpr` 符号常量表示
7. **逐段对应**：RVA 区间 → 这段在做什么
8. **文件末尾**：尚未完成的部分，**逐条列出 RVA，不写猜测版本**

**编译期自检怎么跑**：这些文件**不链接进 DLL**，用一个小测试确认语法与布局断言即可。

> ⚠️ **不要手工维护 include 列表** —— 文件数每轮都在涨（已两次出现"表格数字落后于实际文件数"）。
> 用脚本**自动枚举**目录下全部 `.cpp` 拼成一个 TU；`_` 开头的临时文件排除。
>
> ⚠️ **必须 `#include <string>`**：有的还原文件用到 `std::string` 而自己不 include，靠 harness 提供。
>
> ⚠️ **只编译（`/c`），不要链接**：还原函数内部 `reinterpret_cast` 到硬编码的游戏地址
> （如 `0x140A4F1E0`）并调用游戏内其他函数，测试进程里这些地址不存在
> ⇒ **链接必然报 `LNK2019`，那是预期行为，不是错误**。要验证的是 `static_assert` 与 `offsetof`。

```powershell
$vc = "<VS>\VC\Auxiliary\Build\vcvars64.bat"
$files = Get-ChildItem -Filter *.cpp |
         Where-Object { $_.Name -notlike '_*' } | Select-Object -ExpandProperty Name
$inc = ($files | ForEach-Object { "#include `"$_`"" }) -join "`n"
@"
#include <cstdio>
#include <cstddef>
#include <string>
$inc
int main() { std::printf("files=%d\n", $($files.Count)); return 0; }
"@ | Set-Content _gv.cpp -Encoding UTF8
cmd /c "call ""$vc"" >nul 2>&1 && cl /nologo /std:c++17 /EHsc /W3 /utf-8 /c /Fo_gv.obj _gv.cpp"
"exit=$LASTEXITCODE"    # ← 只看这个：0 = 全部通过（warning 可接受）
```

**拼 TU 时踩过的坑**（新增文件时容易再踩）：

1. **`extern "C"` 不能写在命名空间里被多个 `.cpp` 各声明一次** ——
   C++ 规定"某名字已有 C++ 链接声明后，不能再给它加 C 链接"，同一 TU 里第二次会报
   `C2732 链接规范冲突`。⇒ 这类外部原语声明统一放共享头（在进入命名空间之前）。
2. **同一 TU 里同名 `constexpr` 不能在各 `.cpp` 各定义一次**（`C2374 重定义`）⇒
   共享偏移常量放共享头，各文件只 `#include`。
3. **占位符（如 `0x??`）会直接编译失败** —— 没定的偏移就**别写常量**，
   改在文末"未确定项"里描述。

### 3.6 判类型：vtable → 首参 → 对象大小，缺一必错

**这是本项目最贵的一课**：文化子系统头 4 轮里**归属判错了 3 次**。

**强制判据（第 4 轮起）**：

1. `lea rax, off_XXXX` **认 vtable** → 确定是哪个类；
2. 确认函数**第一个参数是哪个类的实例**；
3. 用**对象大小**交叉检验（**能访问 `+0x444` 的对象一定 > `0x3E0`**）；
4. **才看字段偏移**。

**跳过 ①③ 必错。**

### 3.7 键名 interned：脚本字段名不能用字符串反查

引擎把脚本键名 intern 成**序号 id** 存在解析上下文里，键名字符串集中放在 `0x142xxxxx` 的**名字池**。

| 字段名 | 地址 | xref 数 |
|---|---|---|
| `male_names` | `0x1421C14BC` | **0** |
| `female_names` | `0x1421C16C4` | **0** |
| `dynasty_names` | `0x14216F07C` | **0** |
| `monarch_names` | `0x142076B5C` | **0** |
| `graphical_culture` | `0x14208A42C` | **0** |

⇒ **不能靠字符串反查代码**。池里每个名字前带**非字符串头字节**，名字之间有**未使用空隙**：

```
0x1421C14B8 : '.1'          ← 前一条的名字（头字节 0x00 在前）
0x1421C14BC : 'male_names'  ← 前 1 字节 = 0x00
0x1421C16C0 : '/1'
0x1421C16C4 : 'female_names'
```

**遇到"0 处 xref"的字符串，正确反应是**：去找"**基址 + id**"的寻址方式，
而不是宣布"这个字符串没用"。

### 3.8 崩溃归因：只记录不处理

`AddVectoredExceptionHandler` + **`EXCEPTION_CONTINUE_SEARCH`**（★ **只记录不处理**），
把 `RIP − image_base` 换算成 **RVA** 写日志。

⇒ 崩溃时一眼看出是**哪一站**、落在哪个 RVA。这是把"进游戏静默闪退"变成可诊断问题的关键工具。

### 3.9 隔离研究副本

研究期补丁用编译期开关（如 `#ifdef EU4_MENU_PATCH_RESEARCH`）
⇒ **只允许在写死的隔离路径加载**，避免误挂到玩家的正式安装。

配合插桩脚本里的同名路径校验（`QueryFullProcessImageNameW` 比对完整路径）。

### 3.10 Frida 插桩命名表：一张现成的函数名表

## 5. 要背下来的三条工程数字

| 数字 | 含义 |
|---|---|
| **`0x1FF`（511）** | 引擎里反复出现的**容器槽上限**（文化库哈希桶、显示对象池…）。看到 511 就该想"这是同一套模板"。 |
| **15 字符** | MSVC `std::string` 的 **SSO 分界**（`cap < 0x10` ⇒ 数据内联）。**任何把字符串字段当 `char*` 裸读的代码，只对短串有效。** |
| **`0x3E8`（1000）** | ⚠️ **它不是类型指纹**。引擎里有 **220 处**通用分配用它。**判类型要用 vtable 引用 + 分配点上下文，别用裸常量。** |

## 6. 证据等级速查

| 记号 | 用于 | 含义 |
|---|---|---|
| 【确证】 | 整函数级还原、工程内部记录 | 逐指令对应，行为可判定等价 |
| 【推定】 | 同上 | 依据较充分但非唯一；必须写推理链 |
| 【未知】 | 同上 | 依据不足，只描述行为，用原地址占位 |
| E1 / E2 / E3 | IDB 命名 | 见 §3.2；**< E2 不许改名** |
