# 02 · EU4 人物姓名生成与显示全链路

> 目标：`eu4.exe` v1.37.5.0（Inca），`ImageBase 0x140000000`。全部地址为 **RVA**。
> 本文回答一个问题：**一个角色的「名」和「姓」是何时、在哪里、被谁拼到一起的？**
>
> 这个问题的答案为三件事提供了依据：
> ① 修「权重失效」缺陷要改哪三处；② 「姓前名后」这类改造能挂在哪、覆盖谁；
> ③ 为什么有的做法**看起来对、实际永远不生效**。

---

## 0. 三条先记住的结论

1. **`CMonarch` 里没有"拼好的全名"。** 只有 `name`（`+0x28`）和 `dynasty`（`+0x68`）两个独立字段。
   「姓名」是在**取全名时**才拼出来的 ⇒ **顺序这件事只能在拼合处决定**，事后改字段是不可能的。
2. **存在两条互不相同的链路**，取决于角色类型：
   - **顾问 / 外交官 / 将领** ⇒ 走 `GenerateMonarchName` → **`BuildFullName_Impl`**（姓在**生成期**拼进去）；
   - **统治者 / 继承人 / 配偶** ⇒ 生成期只产生**首名**，姓由 **`CMonarch_GetFullName`** 在**显示期**拼。
3. **`CMonarch` 的实例大小是 `0x120` = 288 字节**，虚表 **`0x141CDCDD8`**，TypeID **357**。
   （早期文档曾记为 128 字节，已由 6/8 个构造点的 `mov ecx,120h` 更正。）

| **`+0x28`** | `CString` | ★ **名**（`data@+0x28 / size@+0x38 / cap@+0x40`） | `0x140A48D39`，`StringAssign` 自 `params+0x08` |
| `+0x48` | ? | | `0x140A48D44` ← `params+0x28` |

| `+0x58` | ptr | 王朝对象（旧记法） | `0x140A48D5C`；为空则 `GetNoReligionSingleton()` |

### 2.1 虚表 `0x141CDCDD8` 的有用槽位

| 槽 | 偏移 | 目标 | 含义 |
|---|---|---|---|
| 2 | `+0x10` | `0x140A4A750` | 大方法（`CMonarch_GetName` 之前那个 2771 字节函数） |
| 3 | `+0x18` | `ParseMonarchNamesKey` | 脚本键 `monarch_names` 的解析方法 |
| 4 | `+0x20` | `CMonarch_InitDynastyName` | 名 / 王朝初始化 |
| 11 | `+0x58` | `0x14008F440` | **恒真**（`mov al,1; retn`） |
| 12 | `+0x60` | `0x14008F450` | **恒假**（`xor al,al; retn`） ← `CMonarch_IsInterregnum` 里那个谓词 |
| 13 / 14 | `+0x68` / `+0x70` | `0x14008F450` | 恒假 |

**★ 由此得到两条化简**（已写进还原文件）：

- `CMonarch_GetFullName` 的 `A && (B || [0x78]==0)` → **`A && [0x78]==0`**；
- `CMonarch_IsInterregnum` 的 `!B && [0x78]` → **`[0x78] != 0`**。

并推出：**非空位期里「拼王朝名」与「拼摄政称号」互斥** —— `[0x78] != 0` 时必走称号那条，
**王朝名永不拼**。这一点在挂显示期钩子时是硬约束。

### 2.2 8 字节 tag 的编码（`+0x20`，已确证）

```
+0  char   tag[3+1]        三字母 tag（默认 / "无效" = "---"）
+4  uint16 countryIndex    ← CMonarch_IsInterregnum 的 shr rax,20h; movsx 取的就是它
+6  uint8  ?
+7  uint8  valid            ← ★ 有效标志：为 0 时调用点直接跳过
```

两处**独立**印证 `+7 = 有效标志`：

- `Country_CreateNewMonarch@0x1403205DE`：`cmp byte [tag+7],0 / jz` —— 无效就不再解析国家；
- `LookupTitleText@0x14072482E`：`shr rax,38h; test al,al; jz` —— tag 无效就不查阶层定义表。

`tag → CCountry` 的惯用法也一致：`shr rax,20h` + 以 `*(g_game+0x118)` 取国家对象。

### 2.3 `CMonarch+0x78` 的持有者（摄政对象，两条来源）

它指向一个 **0x20 字节**堆对象，布局 `{vtable@0, dword@+8, qword@+0x10, dword@+0x18}`：

| | 条件 | 写入点 |
|---|---|---|
| **来源 A**（构造参数） | 仅当 `params+0x78` 标志非零 | `CMonarch_Construct@0x140A48DF4`：`new(0x20)`，vtable = **`off_141C578F8`**，`+0x10` 拷自 `params+0x58+0x10` |
| **来源 B**（调用者直装） | `GovernmentReformStack_IsNativeMechanic(gov,1) == 0` 且源持有者非空 | `Country_CreateNewMonarch@0x140320860`（另一路 `0x140320B93`）：`new(0x20)` → vtable `off_141C578F8`，`+8/+0x10/+0x18` 从**源对象的持有者**整体拷；随后 `mov [rdi+78h],rax`，并把**旧持有者**用 `call qword ptr [old]`（**虚表槽 0**）以 `edx=1` 销毁 |

**✔ `off_141C578F8` = `CRegency`（摄政对象）的虚表。**
证据是**游戏自身的字符串**：该虚表的成员函数 `sub_140A586C0`（槽 4）同时引用类名
`"unknown estate in CRegency"`（`0x141CD350`）与日志源 `...\source\regency.cpp`（`0x141CD370`）；
`sub_140A58A60` 同样引 `regency.cpp`。其余特征（TypeID **357**@`+8`、接口前缀与 `CMonarch` 同位、
槽 0 = 删除式析构）都与"和君主构造参数同源"一致。

⇒ `CMonarch_Construct` 的构造参数 `params+0x58` 里**内嵌的就是一个 `CRegency`**，
`params+0x78` 是"有无摄政"标志。
⇒ 于是 `LookupTitleText` 的 `a1 = &(CRegency->+0x10)`：**`CRegency+0x10` 就是它所挂的
「阶层/摄政定义表」指针**（表在 `+0x468` 数组 / `+0x474` 计数，条目含条件与名字键 `+0x90`）。

**★ `CRegency+0x10` 从哪来**：

| 创建点 | `+0x10` 写入的值 |
|---|---|
| `CMonarch_InitDynastyName` `0x140A499C6` / `0x140A49A77` | **r15** —— 而 r15 在本函数里**只被置 0 过一次**（入口 `xor r15d,r15d`），之后才被 `mov r15,rax` 改成新持有者 ⇒ **这两处写的是 NULL** |
| `CMonarch_Construct@0x140A48DF4`（参数路径） | `params+0x58+0x10`；注意 `InitMonarchConstructParams` **没有**初始化这一格 |

## 3. `BuildFullName_Impl`（`0x313F40`）—— 生成期唯一的拼合处

**这是"名 + 姓"在生成期唯一被拼到一起的地方。** 顾问 / 外交官 / 将领 / 共和制统治者都流经它。

**规模**：`0x313F40..0x31434E`，**1040 B / 278 条指令 / 12 处 call**，**全函数唯一出口**（`retn` @ `0x31434E`）。

```
BuildFullName_Impl(out, sel, a3, a4, …)
  ① 循环：把「名」按空格切段，逐段 StringAppend + 补一个空格
  ② 解析「姓」—— 三个来源，在此汇合：
        a. [rbp+0x78] 王朝名（size 非 0 就直接用）
        b. [a3+0x50] 名字表，按 [a3+0x68] 取模选一项
        c. 全局表回退 NameList_PickByModuloWithFallback
  ③ StringAppend(Src, 姓)
  ④ Src → *out
```

⇒ **出口串恒为「名… 姓」**。

**★ 一个"要多少个参数"的判据方法**：本函数**只有 3 个 xref**：

| 调用者 | 栈写数 | 含义 |
|---|---|---|
| `GenerateMonarchName@0x313F18` | **8 处栈写** | 第 5~12 实参 |
| `Country_CreateNewMonarch@0x32047E` | **12 处栈写** | 全部实参 |
| 1 处 data 引用 | — | 函数表 |

⇒ **元数 = 12，无隐藏调用者** ✓
⇒ ⚠️ 函数体内部读的 `arg_40 / arg_48 / arg_50 / arg_58` 是**调用方栈的残余字节**，
**不是第 13~16 个参数** —— 这是一个很容易被反编译器误导的地方。

### 3.0 ★ 参数语义（`GenerateMonarchName` → `BuildFullName_Impl`）

| 参数 | 内容 |
|---|---|
| `a1` | `country` |
| `a2` | 结果缓冲（`arg0`） |
| `a3` / `a4` | 随机值 / 索引 |
| **`a5`** | ★ **`char*` 性别标志的指针（可读可写！）** —— 函数内有"写回"路径 `0x31418D mov [rax], r10b` ⇒ **生成名字时可能反过来决定性别** |
| `a6` | **王朝名**（`+0x48`） |
| `a7` / `a8` | 标志 |

**`a5` 的来源按类不同**：leader `&v17`（取 `+0x70`）· 顾问 `a5 = rdi` · envoy `+0x40` · 统治者 `&pRulerTemplateData`（**存疑**）。

> ★ **"性别字段的偏移不统一"** 是一个容易踩的坑：
> leader `+0x70` · envoy `+0x40` · 顾问 `+0x2BD` · 统治者**可能不持久化**。
> **通用的是 `a5` 这个参数，不是某个固定偏移。**

### 3.0.1 序言 / 尾声（决定钩子的栈语义）

```asm
; 序言
push  rbp / r14 / r15
sub   rsp, 110h
mov   r14, r8          ; ★ 第 3 参数 → r14（P6/P7 用它取文化）
mov   rdi, rcx

; 尾声
mov   rax, rdi                    ; ★ return out
lea   r11, [rsp+110h]
从 [r11+20h..38h] 恢复 rbx/rsi/rdi/r12
mov   rsp, r11
pop   r15 / r14 / rbp             ; ← 恰好 5 字节（P4 覆盖的就是这三条）
retn                              ; ← 全函数唯一出口
```

⇒ 入口 `[rsp]` = 保存的 r15 · `[rsp+8]` = r14 · `[rsp+16]` = rbp。

**关键调用点**：

| RVA | 内容 |
|---|---|
| `0x3140BE` | `WeightedNameList_SplitByMarker` |
| `0x314210` | `StringSplitByChar(…, ' ')` 切段 |
| `0x31425B` / `0x314272` / `0x3142F7` | **三次 `StringAppend`** |
| `0x3142CD` | `NameList_PickByModuloWithFallback`（= 姓的来源②） |
| `0x31405C` / `0x314103` | `WeightedNameList_GetByModIndex`（**唯一调用者**） |
| `0x31432B` | `mov rax, rdi`（= `return out`） |
| `0x314349` / `34B` / `34D` | `pop r15 / r14 / rbp`（`41 5F 41 5E 5D`，**恰好 5 字节**） |
| `0x31434E` | `retn`（**全函数唯一出口**） |

**★ 哨兵与空结果**：`0x2357D70`（空王朝单例）与"返回 0"都表示"没有"；
全落空 ⇒ `*out` 置空串（`cap = 0xF`）。

**★ 主循环的一个细节**：**首字符是 `#` 的段整段跳过**，否则段后补一个空格。

**★ 一处独立缺陷（未纳入补丁）**：`BuildFullName_Impl` 对
`WeightedNameList_GetByModIndex` 的返回值 **`*(_BYTE*)(v15+36)` 未判空**
⇒ 空表会读地址 `0x24`。

**★ 三个被读通的关键被调函数**：

| 地址 | 名称 | 功能 |
|---|---|---|
| `0x1417047C0` | `StringSplitByChar` | 按**分隔字符**把 `CString` 切成 32 字节元素的 `CString` 数组（`memchr` 找分隔符 → 每段切片 move 进数组 → 末尾补最后一段）。★ `BuildFullName_Impl` 在 `0x314210` 传的 `0x20` 是**空格分隔符**，不是"kind" |
| `0x140094E60` | `StringArrayDestroy` | `{begin,end,cap}` 的 `CString` **数组**析构：每 32 字节一个元素逐个 `StringFree` → 释放缓冲（含 `>=0x1000` 对齐块检查）→ 三个字段清零 |
| `0x14008F670` | `InitLocalizationArg` | 就地初始化 **0x68 字节的本地化参数元素**：`CString#1{ptr@+0x08,size@+0x18,cap@+0x20=0xF}`、`CString#2{ptr@+0x30,size@+0x40,cap@+0x48=0xF}`，其余清零 |

**★ 12 个实参已逐指令确证**（`GenerateMonarchName` 是主要调用者）：

- `a3` / `a4` = **随机值**；
- **`a5` = 名字段数组出参**（`{begin,end}`，元素 32 字节）；
- `a6` = 出参；
- **`a7` / `a8` = 索引**（`a7` 用于 `WeightedNameList_GetByModIndex`；`a8` 用于"32 字节元素数组按 `a8 % count` 取项"）。

### 3.1 `GenerateMonarchName`（`0x313D90`）—— 谁喂给它两张表

**427 B / 100 条指令 / 4 处 call。**

```
选两张表：
  名字表   ← country+0x1170  或  Country_ResolveMonarchNameTable(country)   ⇒ 第 4 实参 r9
  王朝名表 ← country+0x1110  或  Country_ResolveDynastyNameList(country)    ⇒ 第 5 实参
交给 BuildFullName_Impl
第 2 实参 = country[0x20]    第 3 = country[0x1228]（文化）
第 6 实参 = country[0x2870]
```

★ **共和制统治者取名也走 `BuildFullName_Impl`** ⇒ 生成期那一组钩子对共和制统治者是生效的。

### 3.2 两个"逐字节同构的孪生访问器"

这两个函数**规模完全相同（各 99 B / 24 条指令 / 0 处 call，都是叶子）**，
唯一差别是返回的偏移：

| 地址 | 名称 | 返回 |
|---|---|---|
| `0x2D08E0` | `Country_ResolveMonarchNameTable` | `culture + **0x1170**`（`monarch_names` 加权表） |
| `0x2CE830` | `Country_ResolveDynastyNameList` | `culture + **0x1110**`（`dynasty_names` 数组） |

`a2 = 0` 时 `Country_ResolveMonarchNameTable` 会先解析「**性别变体**」：
变体 id ≠ 本文化 id ⇒ **换文化对象**。
（这一条顺带补齐了 `Culture` 的 `+0xBC0 / +0xBC7 / +0xBC8 / +0xBCF / +0x1170` 字段语义。）

> ⚠️ **一个反复踩的坑**：`+0x1110` / `+0x1170` **不能**只记成"文化字段"。
> 现场证据（`sub_140283D20`，`countrydatabase.cpp` 国家记录读取器）表明：
> `Country_Resolve*` 返回的是**"当前对象"**（可能是变体文化、也可能是**国家自己**），
> 随后才 `add rdx/rcx, 1110h/1170h`。
> ⇒ **读表的人有两个，国家是其中之一**；两个**填充者仍未定位**。

## 4. 显示期唯一的拼合处：`CMonarch_GetFullName`（`0xA4B2C0`）

**752 B / 182 条指令 / 24 处 call**（函数边界取自 `.pdata` 的 `RUNTIME_FUNCTION`，非推测范围）。
**55 个调用点**。

```
CMonarch_GetFullName(CMonarch *a1, out):
    StringAssign(out, a1+0x28, len)                 // ① 名
    ...（入口那段 strlen 是【内联算第 3 参】，不是函数内部又量一遍）
    v10 = a1[13] + 8                                // ② 王朝名 = *(CMonarch+0x68)+8
    Src = " ";  StringAppend(Src, v10, ...)          //    Src = " 朱"
    StringAppend(out, Src, ...)                      //    out = "瞻基 朱"  ← 分隔符是硬编码空格
```

**但完整行为比上面这段复杂** —— 它先按 `CMonarch_IsInterregnum` **分流**：

| 支路 | 行为 |
|---|---|
| **空位期**（`[0x78] != 0`） | 走**完全不同的另一条支路**：只拼本地化键 `INTERREGNUM` / `ESTATE_INTERREGNUM`，且**不补 `)`** |
| **非空位期** | 拼王朝名，之后统一补 `" (" + Loc("REGENT_TITLE") + ")"` |

**⇒ 「名」和「姓」在对象里是两个独立成员，由 `CMonarch_GetFullName` 才拼到一起。**

### 4.1 这对补丁意味着什么（关键）

- `BuildFullName_Impl`（生成期）**只在顾问 / 外交官 / 将领 / 共和制统治者那条链上**；
- 统治者虽也会调 `GenerateMonarchName`，但结果**随即被 `GenerateMonarchNameAlt` 覆盖**（见 §5.1）；
- **字符串层（`CMonarch+0x28`）永远只有名 ⇒ 任何在那里做的"姓名顺序"处理对统治者无效**；
- **唯一能同时看到「名」和「姓」的地方 = `CMonarch_GetFullName`**。

> ★ **第三方双字节补丁为什么只能对统治者有效、且只能用空格分隔**：
> 它在**姓名出口**读到 mod 的 `dynasty_names` 里带的 `0xBF` 字节 ⇒ 据此把姓搬到最前；
> **但它只能用原来那个空格当分隔符**，所以多段名会与姓粘连。
> 这正是它做不到"配置分隔符"的原因。

### 6.1 `CommitMonarchName`（`0xA52140`）

⇒ **继承人 · 统治者 · 配偶共用**。

```

② 在名字里找 '#'：找到 ⇒ ordinal = atoi('#' 之后)；否则 0

⑤ 应用文化规则：for (r ∈ v10+0x1308 数组, 共 *(v10+0x1314) 个)
```

### 6.2 `Rule_ApplyNameOrder`（`0xA51050`）—— 同名统治者的世数

**791 B / 227 条指令 / 11 处 call**；调用者：`CommitMonarchName` 2 次、`FinalizeMonarchName` 2 次。

```
① 取"名字源"：
     if (!CMonarch_IsInterregnum(cm) || cm->name.size != 0)   // ★ a1[7] = *(cm+0x38) = name.size（不是标志）
         Block = cm->name                                     // ★ a1[5] = *(cm+0x28)
     else
         LookupLocalizedString(Block, "INTERREGNUM", 0, 0)
② StringSplitByChar(Block, rulerSegs, ' ')                     // 统治者名字按空格切段
③ if (统治者名字段数 > hashIndex) {
       逐段比对：模板段[0..hashIndex-1] vs 名字段[0..hashIndex-1]
                 （size 相等 【且】 memcmp 全等；一旦不等即永久置 0）
       if (全等) {
           value = 解析罗马数字(模板段[hashIndex])              // 即 '#' 段

       }
   }
④ StringArrayDestroy(rulerSegs)
```

⇒ 模板形如 `Karl#IV`：**只有新统治者的名字与模板前半部分逐段一致时，`#` 段的世数才被采用** ✓
（这正是"同一名字的第几世"在数据里的表达方式。）

### 6.3 罗马数字字符集 = `{I, V, X, L}`

掩码是**十进制 40969 = `0xA009`**，对 `c − 'I'` 取位
⇒ 只认 `I`(0) / `L`(3) / `V`(13) / `X`(15)，**不含 `C`/`D`/`M`** ✓
（⇒ 世数量级落在几十以内，符合游戏用法。）

解析是经典"减法式"：`cur > prev && prev` ⇒ `value += cur − 2·prev`（处理 IV / IX / XL）。

**运行期自检**：`IsRoman('I','V','X','L')=1`、`IsRoman('C','M')=0` ✓

### 6.4 `RomanNumeral_FromInt`（`0xA90400`）—— 另一侧

**270 B / 69 条指令 / 8 处 call。正整数 → 罗马数字，只用 `{I,V,X,L}` 的加法式**
⇒ **`90 = LXL`、`100 = LL`**（不是 `XC` / `C`）。

★ 与 `Rule_ApplyNameOrder` 的解析字符集掩码 `0xA009` **完全对称** —— 两条独立还原互相确认 ✓

**`0x2D2D2D`（小端读作 `"---"`）在引擎里反复出现，是一个"空/无效"哨兵值。**

| 出现处 | 位置 |
|---|---|
| `CMonarch_InitDynastyName` / `InitMonarchConstructParams` | 名字默认置 `"---"`、`cap=15`、vtable、TypeID 357 |
| `Segment_Construct` | 段的 `+0x40`/`+0x48` 默认就是 `0x2D2D2D` |
| `DisplayObject_Construct` | `+0x50`/`+0x58` 默认 `0x2D2D2D`（**第 3 次印证**） |
| `Country_GenerateRulerName` | 内部变量 `v114 = 2960685` = `0x2D2D2D` |

> 判据价值：看到一个对象的 `+0x40`/`+0x48`/`+0x50` 是 `0x2D2D2D`，
> 基本可以断定"这是刚构造、还没填内容"的显示段/显示对象。
