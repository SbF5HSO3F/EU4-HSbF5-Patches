## 1. 一句话全貌


## 5. 名字表机制（**已闭合**）

```
脚本：male_names = { NAME = { "Erik" "Lars" } }        ← 键名池 0x1421C14BC
      female_names = { … }                            ← 键名池 0x1421C16C4
解析：add rbx, 0C8h / 0E0h  →  按 '\n' 切分 hdr+0x18  →  strncmp(条目名,"NAME")
      · 命中 "NAME" ⇒ LookupLocalizedString(值) → push_back 32 字节 CString
      · 否则        ⇒ 原样拷贝 32 字节 CString
容器：{alloc@+0x00, begin@+0x08, end@+0x10}，元素 0x20
```
★ **三方吻合**：`StringArrayDestroy`（E1 命名）· `PickNameFromCultureLists` 的 `>>5` · 本目录的机器码。

## 10. ★★★ 本子系统的**直接应用**：长文化名匹配失败（SSO 分界）

> 详见 **`notes\诊断-长文化名SSO分界.md`**。这是本次文化逆向的**原始动机**，已定位到根因与具体代码位置。

**一句话**：文化名是 `std::string`；**`文化对象 + 0x48` 在短名（≤15 字符）时是字符数据，在长名（≥16）时是堆指针**。
补丁把 `+0x48` 无条件当 `char*` 读 ⇒ **`shandong_culture`（恰好 16 字符）读到指针字节**。

| 事实 | 值 |
|---|---|
| SSO 阈值 | **15 字符**（`cap < 0x10` ⇒ 内联） |
| `swedish` | 7 字符 ⇒ SSO ⇒ 裸读**碰巧正确** |
| `shandong_culture` | **16 字符** ⇒ 堆 ⇒ 裸读得到**指针字节**（"非 ASCII 垃圾、涉及多个国家"正是指针值） |
| 出问题的两处 | `monarchnamefix.cpp` **L1916**（P6 捕获 = 主犯）与 **L886**（P8 诊断） |
| 现成的正确读法 | `cultureconfig.h::cc_cstr_field`（`+0x120` + **SSO 判据**）—— 已在用，但那两处没走它 |
| 因果 | `g_cult_name` 只由 L1916 那条路径写 ⇒ 长名写不进 ⇒ `cc_lookup_name` 拿不到候选名 ⇒ **整份日志从不出现该文化**（与 `补丁逻辑解析.md` §10.1 完全自洽） |
