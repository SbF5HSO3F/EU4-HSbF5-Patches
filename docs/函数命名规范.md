# EU4 逆向函数命名规范

> **v1 草案 → v2（本版）**。本版在你原稿基础上做了三件事：
> ① 修正原稿中的拼写与语义问题；② 用 IDB 实证（RTTI 类名、既有 762 个命名）补齐"类名/作用域"部分；
> ③ 补出原稿缺失的 12 个章节（标注、置信度、IDA 专用规则、台账、整改清单等）。
> 凡是**改动你原稿**的地方都标了「原稿 / 修订」，便于你逐条取舍。

适用范围：`eu4.exe` v1.37.5.0（`SHA256 9AD3EFE1…`）的 IDA 数据库 `ida_dbs\eu4.exe.i64` 中的
函数 / 全局 / 数据 / 类型 / 注释命名。**不约束**我方补丁工程的源码（`src\`）与文档文件名（另有 §13）。

## 0. 三条铁律

| 编号 | 铁律 | 理由 |
|---|---|---|
| **R1** | **证据优先**：没有 ≥E2 证据（§9）就**不许改名**，保持 `sub_` 并把假设写进注释 | 一次误判会污染整个 IDB，且改名后很难分辨哪些是猜的 |
| **R2** | **不覆盖真名**：CRT / std / boost / SDL / Steam / EOS / TBB / Nakama / FreeImage / `unknown_libname_*` 一律不动 | 这些是 ground truth，改了就丢了唯一的库级信息 |
| **R3** | **不猜类归属**：用 `Class::Method` 之前必须验证 `this` 的 vtable 属于该类 | 类名错 = 语义错，比 `sub_` 更有害（`sub_` 至少不骗人） |

> R1 是有代价得来的：本项目早期我曾把"继承人随机姓名"的来源判成文化的 `male_names`，
> 实际是 `common/countries/*.txt` 的 `monarch_names`。当时我只有 E3 级证据却当 E1 用。
> **所以"证据等级"和"改名门槛"必须写进规范。**

## 1. 函数开头（动词前缀）— 含返回值契约

原稿给了 4 个，下面补全并**明确每个动词的返回值契约**（这比"意义"更重要，因为它可被检查）。

### 1.1 取用类

| 前缀 | 契约 | 失败时 |
|---|---|---|
| `Get*` | **必须成功**、无副作用、无失败路径 | 不允许失败；若可能失败则改 `TryGet*`/`Find*` |
| `TryGet*` | 返回 bool，结果经出参返回 | 返回 0，出参不动 |
| `Find*` | 可能找不到，返回指针/索引 | 返回 `NULL` / 无效值 |
| `Resolve*` | 由**间接标识**（tag / id / 名字）解析出对象 | 返回 `NULL` |
| `Lookup*` | 查表命中，O(1) 语义 | 返回 `NULL` |
| `Peek*` | 只读窥视，不改状态、不消耗 | — |

> **原稿修订**：`GetProvinceByID(id)` 用的是 `Get`，但"按 ID 查"本质是**可能失败的查找**。
> 应为 `FindProvinceByID` 或 `ResolveProvinceByID`。另外原稿描述"获取 `Tag` 的特定省份"本身矛盾
> —— 省份不属于国家。**修订**：`ResolveProvinceByID(id)`：「由省份 ID 解析出 `CProvince` 对象」。

### 1.2 判定类（**必须返回 bool，必须无副作用**）

`Is*`（属性判断）、`Has*`（是否持有/含）、`Can*`（能力/权限判断）、`Should*`（策略判断）、`Was*`/`Did*`（历史标志）。

> 原稿 `Tag::IsRepublic()` ✓ 合理，但按 R3：`Tag` 不是类名（见 §5），应写作 `Country_IsRepublic()`
> 或（在 RTTI 证实国家类名后）`CCountry::IsRepublic()`。

### 1.3 变更类

`Set*`（直接赋值）、`Add*`/`Remove*`（集合增删）、`Clear*`（清空）、`Reset*`（复位到初值）、
`Toggle*`（布尔翻转）、`Mark*`（打标志）、`Touch*`（使失效/标脏）。

### 1.4 创建销毁类

`Create*`（生成一个游戏对象，通常有副作用并注册）、`Destroy*`、`Alloc*`/`Free*`（裸内存）、
`Clone*`/`Copy*`、`Ensure*`（不存在则创建）、`Init*`（就地初始化已分配对象）、`Fini*`（与 `Init*` 配对）。

> 原稿 `Tag::CreateRuler()` ✓ 动词正确；按 R3 改类名即可。

### 1.5 流程与算法类

`Load*`/`Save*`、`Parse*`（脚本/文本解析）、`Serialize*`、`Build*`（组装复合对象）、
`Update*`（增量刷新）、`Tick*`（每帧/每日推进）、`Apply*`（**有副作用**地施加）、
`Calc*`（**纯计算**，无副作用）、`Evaluate*`（求值脚本表达式）、`Validate*`（校验并报告）、
`Dump*`（调试输出）。

> **原稿修订**：原稿写作 `GetTaxInccomeForm(args)`：
> ① `Form` 是 `From` 的**拼写错误**；② `Inccome` 是 `Income` 的拼写错误；
> ③ `Get…From(args)` 语义太泛 —— 若是在算收入，应用计算动词。
> **修订**：`CalcTaxIncomeFromModifiers(pMods)` / `CalcTaxIncome(…)`。

### 1.6 选取与随机类（本项目的核心领域，原稿缺失）

`Pick*`（从集合中选一个）、`Roll*`（掷随机数）、`Randomize*`、`WeightedPick*`（按权重选）、
`Select*`（按规则选而非随机）。

> 这组不是装饰性的。我们修的那个缺陷正出在这里：
> `WeightedNameList_PickByRandomIndex` / `PickNameFromCultureLists` 的命名恰好让缺陷读起来一目了然。

### 1.7 日志与调试类

`Log*`（写日志）、`Trace*`、`Assert*`、`Report*`。

### 1.8 回调与事件类

`On*` —— **仅**用于"被系统回调的钩子"（如 `OnDailyTick`），不要当作普通动词。
`Handle*` —— 用于处理外部消息/命令（如 `HandleDiplomaticAction`）。

### 1.9 我方补丁相关（与游戏函数隔离）

`Patch_*`：指我方补丁引入/包装的函数，永不用来命名游戏原生函数。

## 2. 介词与词序

### 2.1 修订原稿

原稿的 `By` / `Form` 方向是对的，但有三个问题：

1. **`Form` → `From`**（拼写）。
2. **介词不是"函数开头"** —— 它是词序规则，不是前缀。原稿把它和 `Get`/`Is`/`Set`/`Create` 并列在
   "函数开头"之外，但也没说清它出现在哪里。**规范**：介词只出现在**中间或结尾**。
3. **不该滥用介词**：当"来源/依据"就是唯一参数时，直接省略介词更清楚。

### 2.2 词序模式

```
<动词><对象>                      GetRuler
<动词><对象>By<键>                FindCharacterByID
<动词><对象>From<来源>            CalcTaxIncomeFromModifiers
<动词><对象>In<容器>              FindProvinceInRegion
<动词><对象>At<位置/时刻>          GetProvinceAt(index)
<动词><对象>With<工具/依据>        PickNameWithWeight
<动词><对象>For<受益者>            CreateHeirFor(country)      ← 罕见，优先用参数
<动词><对象>To<目标>               ConvertReligionTo(rel)
```

**介词选用表**：`By` 键/依据；`From` 来源；`In` 容器/范围；`At` 位置/时刻；`With` 手段；
`For` 受益者/目的；`To` 目标；`Of` 所属（尽量避免，`GetXOfY` 多数应写成 `Y::GetX`）。

### 2.3 何时**不用**介词

如果只有一个候选来源，介词是噪音：

| 啰嗦 | 更好 |
|---|---|
| `GetRulerFromCountry()` | `Country_GetRuler()` |
| `GetNameByIndex(i)` | `GetNameAt(i)` 或直接把 `i` 作为参数写在原型里 |

**判据**：只有当函数名脱离原型后会产生歧义（"从哪儿取？"）时才加介词。

### 2.4 大小写与词的边界

- 介词在函数名中**首字母大写**：`From`、`By`、`In`（不是 `from`）。
- 整名 PascalCase，**不用下划线分词**（下划线仅保留给 §6 的模块标记与 §7 的既定后缀）。

## 3. 缩写与词汇

### 3.1 铁则

> **函数名与类名禁止缩写；局部变量鼓励缩写。**

理由：函数名是全局可见的检索键，写全才能 grep 到；局部变量是局部的，短名能显著提升 Hex-Rays 可读性。

例外：已是**既定专名**的缩写可用 —— `ID`、`AI`、`UI`、`HRE`、`GUI`、`DLC`、`MP`、`SP`。

### 3.2 术语表（函数名里写全，局部变量可缩写）

| 概念 | 函数名用 | 局部变量可用 |
|---|---|---|
| 国家（三字母标识） | `Tag`（数据）/ `Country`（对象） | `tag`, `pCountry` |
| 省份 | `Province` | `pProv`, `provID` |
| 角色（统治者/继承人/配偶/顾问的基类） | `Character` | `pChar` |
| 统治者 / 继承人 / 配偶 / 顾问 | `Ruler` / `Heir` / `Consort` / `Advisor` | `pRuler`, `pHeir` |
| 君主（含模板与实例两个概念） | `Monarch` | `pMonarch` |
| 王朝 | `Dynasty` | `pDyn` |
| 文化 / 文化组 | `Culture` / `CultureGroup` | `pCul`, `pCulGroup` |
| 宗教 | `Religion` | `pRel` |
| 阶层 / 理念 / 任务 / 决议 / 事件 | `Estate`/`Idea`/`Mission`/`Decision`/`Event` | `pEstate`… |
| 修正 / 触发器 / 效果 / 作用域 | `Modifier`/`Trigger`/`Effect`/`Scope` | `pMod`, `pTrig` |
| 贸易节点 / 贸易品 | `TradeNode` / `TradeGood` | `pNode`, `pGood` |
| 单位 / 陆军 / 海军 / 舰队 | `Unit`/`Army`/`Navy`/`Fleet` | `pUnit`… |

> `Tag` 与 `Country` 必须区分：**`Tag` 是数据（3 字母标识 + 索引），`Country` 是对象。**
> 这也是原稿 `Tag::GetRuler()` 的问题来源 —— `Tag` 不该做类名（§5）。

### 3.3 局部变量前缀（提升反编译可读性）

`p`指针 `pp`二级指针 `n`/`i`/`k`整数与下标 `b`布尔 `f`浮点 `s`字符串 `v`值 `fn`函数指针 `sz`大小。

## 4. 大小写总表

| 实体 | 规范 | 例 |
|---|---|---|
| 函数 / 方法 | PascalCase | `ResolveRulingDynasty` |
| 类 / 结构体 / 枚举 | 游戏类用 **RTTI 原名**；自造辅助类型 PascalCase 无前缀 | `CString` / `NameEntry` |
| 枚举成员 | PascalCase 或 UPPER_SNAKE（择一并保持一致） | `Gender_Male` |
| 全局变量 | `g_` + PascalCase | `g_pGameState` |
| 静态成员 | `s_` + PascalCase | `s_DynastyDatabase` |
| 结构体成员 | 小写或 camelCase（**不加** `m_`：IDA 已限定所属结构体） | `weight`, `genderFlag` |
| 局部变量 | 前缀 + camelCase（§3.3） | `pCountry`, `nIndex` |
| 宏 / 常量 | UPPER_SNAKE | `MAX_RULER_AGE` |
| **脚本键** | **原样 snake_case（ground truth）** | `monarch_names`, `define_heir` |
| 脚本实现函数 | `Effect_<CamelKey>` / `Trigger_<CamelKey>` / `Command_<CamelKey>` | `Trigger_HasProvinceModifier` |

> **脚本键为什么必须保持 snake_case**：它是数据文件里的字符串，是**唯一确定**的事实。
> 但"字符串键"与"实现函数"要分开命名 —— 原稿没有涉及这一层，而 EU4 逆向里这层极其重要
> （`common/` 下每个 effect/trigger 都有一个 C++ 实现）。

## 5. 类名与作用域（**原稿最需要修订的部分**）

### 5.1 实证：游戏用的是 MSVC `C` 前缀，不是 `Tag`

本 exe **带完整 RTTI**。从 `.rdata` 提取到 **161 个类型描述符**，其中非库类型 70 个。可靠样本：

```
CString   CFixedPoint   CRootTrigger   CException   CFileException
CChoiceException   CClockException   CMultiStopMissionAndPerformAction
CCustomCountryLoadTask   CCustomCountrySaveTask   CNDSessionUpdateTask
(anon)::CCreateChecksumTask   CCreateFileListFromManifestTask   CModifierPictureVerifierTask
CEU4Application   CPdxArray   CList   CPdxMeshObject   CRelationsContainerArray
CWar  CAlliance  CRoyalMarriage  CMilitaryAccess  CSubsidies  CGuarantee  CDependency
CFleetAccess  CWarning  CImproveRelation  CCondition… （外交动作一整套）
```

**结论**：
1. 游戏类 = `C` + PascalCase（MSVC 惯例）。
2. Paradox 框架类 = `CPdx*`（`CPdxArray`、`CPdxMeshObject`）。
3. 外交动作 = `C<动作名>`（`CRoyalMarriage`…），与数据目录 `common/diplomatic_actions`、
   `common/new_diplomatic_actions` **一一对应** —— 这是数据侧与代码侧互相印证的绝佳例子。

> **原稿修订**：`Tag::GetRuler()` → 类名 `Tag` 不成立。若已证实国家类名（本样本里**未出现** `CCountry`），
> 写作 `CCountry::GetRuler()`；否则按 §6 写作 `Country_GetRuler()`。

### 5.2 RTTI 能给什么、不能给什么（实测结论）

**能给：真实的类名拼写。**
已从 `.rdata`/`.data` 提取 **507** 个类型描述符，剔除库类型后得到 **66 个类名 token**，
落盘于 `notes\rtti-vocabulary.md`。其中包含：

- 核心值类型：`CString`、`CFixedPoint`
- 脚本/触发器：`CRootTrigger`、`STokenModifierEffect`
- 应用与框架：`CEU4Application`、`CPdxArray`、`CPdxMeshObject`、`SPdxParallelFor`
- 外交动作整套：`CWar`、`CAlliance`、`CRoyalMarriage`、`CMilitaryAccess`、`CSubsidies`、
  `CGuarantee`、`CDependency`、`CFleetAccess`、`CWarning`、`CImproveRelation` …（与
  `common/diplomatic_actions`、`common/new_diplomatic_actions` 数据目录对应）
- 容器：`CRelationsContainerArray`（出现 22 次，外交关系容器）、`CList`、`CBlob`、`CMessage`、`CModifier`

**不能：判定"某函数属于哪个类"。**
实测 507 个描述符里只有 **82 个**被 COL（Complete Object Locator）引用，
而这 **82 个全部是 MSVC 运行时内部** —— locale facets（`ctype`/`moneypunct`/`num_get`…）、
异常类（`exception`/`bad_alloc`…）、Concurrency 接口，以及 MSVC 自带 demangler 的
`charNode`/`DNameStatusNode`/`pairNode`。

**游戏类一个都没有**：`CString`、`CFixedPoint`、`CRootTrigger`、`CCustomCountryLoadTask`、
`CMultiStopMissionAndPerformAction` 的 COL 引用数都是 **0**。

> ⚠️ **本版对自身草案的更正**：上一版 §5.3 建议"用 vtable 反查类归属"，
> 该法**对游戏类不成立**，已按下文改写。

还有一条关键事实：**`CCountry`、`CProvince`、`CCharacter` 在 RTTI 中完全不存在**。
游戏里最重要的三个类拿不到真名 ⇒ 国家/省份/角色相关代码的**正确出路是 L2（模块标记）**，
这也正好说明现有的 `Country_CreateNewHeir` 这类命名是合规的，而不是"退而求其次"。

### 5.3 三层规则（据实测修订）

| 层 | 条件 | 命名形式 | 实测可得性 |
|---|---|---|---|
| **L1** | RTTI 中有该类名，**且**能用 §5.4 的证据确认成员归属 | `CClassName::Method`（必须用 RTTI 原拼写） | 游戏类几乎不可得；仅 12 个类拥有自己的描述符 |
| **L2** | RTTI 无，但已知日志来源 `xxx.cpp:line` | `<Module>_Function`（§6） | **主路径** |
| **L3** | 两者都无 | 保持 `sub_`，假设写入注释 | — |

### 5.4 没有 vtable 时，如何建立"成员归属"证据

按证据强度排序（都可支撑 L1 的 `::`，但要求 ≥E2）：

1. **`this` 字段自洽** —— 函数读写的 `*(this + 0xNNNN)` 偏移已被另一函数确证属于类 X
   ⇒ 强烈指向同一类。**最实用的一条。**
2. **构造/析构配对** —— `ctor` 写入的字段与目标函数读取的字段一致。
3. **数据文件字段映射** —— `common/` 或存档字段名与结构偏移一一对应。
   本项目已用此法确证 `monarch_names` 表头 `+16/+20/+24/+32/+48` 与 40 字节元素布局。
4. **调用者收敛** —— 全部调用者都处于类 X 的上下文。
5. **`typeid`/`catch` 引用** —— 代码里 `lea` 指向某类型描述符，只能证明"提到过这个类"，**最弱**。

**在拿到第 1～4 条之一之前，不要使用 `::`（R3）。**

### 5.5 `::` 对 IDA 的语义影响（必须知道）

IDA 把 `A::B` 视为 **C++ 成员函数**，会据此推断 `this` 指针与调用约定。x64 下 `this` 在 `rcx`，
这在多数情况下**恰好正确**，是有利的；但若把自由函数硬写成 `A::B`，IDA 会做出错误的
`this` 推断，后续类型传播会一路错下去。**所以 R3 不是洁癖，是技术必要。**

### 5.6 类名的第二权威来源：日志字符串（**比 RTTI 更有用**）

RTTI 只覆盖"被多态使用的类型"，而本作**游戏类几乎全部没有 RTTI 描述符** ——
已核实 `CCountry`、`CMonarch`、`CProvince`、`CRuler`、`CCharacter` 在 507 个类型描述符中**全部不存在**。

但日志/断言字符串里带着**开发者亲手写的** `ClassName::MethodName`：

```
CCountry::Clear() %s                                  @0x141C57E90
CCountry::SetCapital set _bUpdateSupplyRangeCache     @0x141C591A8
CCountry::GenerateNonHistoricalAttributes %s %d       @0x141C58198
CProvince::Conquer: %d, %s                            @0x141CD8A20
CMonarch::SetAttachedLeader _LeaderID %i              @0x141CDC848
CDefineRulerEffect::Execute %i                        @0x141CA69F8
CDefineHeirEffect::Execute %i                         @0x141CA6B20
CPapacyInstanceData::ChooseNewWeightedPope %i %d      @0x141D222B0
CCountryModifiers::EState::CALCULATING when called from …  @0x141CCC758
```

已全量提取 **82 个类 / 154 个 `Class::Method`**，落盘 `notes\日志字符串类名方法名.md`。

**用途与限制（务必分清）**：

| 它能证明 | 它不能证明 |
|---|---|
| 该类名/方法名的**真实拼写**（E1，开发者自己写的） | 哪个**地址**实现了它 —— 一条日志串可能来自任意调用方 |
| 方法名可直接复用，如 `SetCapital`、`AddOwnedProvince` | 该方法的参数与返回值 |

⇒ **绑定地址的方法**：查该字符串的交叉引用，落到哪个函数，该函数即为该方法（或其调用者）。
拿到"字符串地址 + 引用函数地址"这一对之后，才可用 `ClassName::Method`（L1，≥E2）。

> ⚠️ **两个来源不得混用**：
> `rtti-vocabulary.md` = **RTTI 类型描述符**（66 个 token，全部无 vtable）；
> `日志字符串类名方法名.md` = **日志/断言字符串**（82 类 154 方法，含 `CCountry`/`CMonarch` 等）。
> 前者回答"哪些类型参与了多态"，后者回答"开发者把类叫什么"。**判断类名拼写时以后者为准。**

## 6. 模块标记（类未知时的退化形式）

当只有 `xxx.cpp:line` 这种日志证据（这是 EU4 里最可靠的证据来源之一），
用 **`<Module>_<Function>`**，`Module` = 源文件主名转 PascalCase。

| 日志来源 | 模块标记 |
|---|---|
| `country.cpp` | `Country_` |
| `heir.cpp` | `Heir_` |
| `random.cpp`（clausewitzlib） | `Random_` |
| `gamestate.cpp` / `persistent.cpp` | `GameState_` / `Persistent_` |
| `effectimplementation.cpp` | `EffectImpl_` |
| `tradenodedefinition.cpp` | `TradeNodeDef_` |
| `opinion_modifier.cpp` | `OpinionModifier_` |
| `bitmapfont.cpp` / `localize.cpp` | `BitmapFont_` / `Localize_` |

**这正好解释并保留了现有命名**：`Country_CreateNewHeir`、`Random_GetGlobalMT` 都符合本规则 ✓

**但反过来**：没有日志证据时**不要凭空发明模块名**。这正是现有语料里的问题（见 §14）。

## 7. IDA 专用规则

### 7.1 绝对不可改名

- CRT / 标准库（`Sprintf`、`Vsnprintf`、`InitializeCriticalSectionEx`、`?do_get@…` 等 mangled）
- 第三方：SDL、Steam（`SteamAPI_*`）、EOS、TBB、Nakama、FreeImage、boost、luabind
- `unknown_libname_*`、`j_*`（thunk）、`nullsub_*`
- 形如 `name_0` / `name_1` 的**重复名后缀**（IDA 自动加，不要当成版本区分）

### 7.2 名称字面规则

- 允许：`A-Z a-z 0-9 _ ::`
- **禁止**：空格、`.`、`$`、`?`、`@`（后三者会让 IDA 当 mangled 名解析）、
  开头/结尾下划线（保留给编译器与 CRT）
- **禁止把地址写进名字**（`sub_14030D200` 里的地址由 IDA 维护；改名后不要携带地址）
- 建议长度 ≤ 40 字符（含 `Class::` 前缀）
- **禁止重名**：不要给两个不同函数同名（会破坏 xref 与脚本检索）

### 7.3 局部变量 / 栈变量 / 结构体

- 反编译器生成的 `v1`/`a1`/`a2`：**只在确实理解后才改**；`this` 应显式改名
- 栈变量用 §3.3 前缀
- 结构体成员按真实偏移顺序命名；未知填充用 `padding_XX`
- 位域/标志位：成员名 + 注释写清位含义（如 `flags` + `/* bit0: isFemale */`）

### 7.4 类型与 vtable

- `vftable` 类名与 RTTI 一致：`??_7CString@@6B@`
- 自造结构体 PascalCase，并在类型注释里写**证据**（偏移来源、验证方式）

## 8. 注释规范（原稿缺失，但对长期项目最关键）

### 8.1 函数注释模板（可直接复制）

```
[what]  一句话说清做什么
[evidence] 证据：日志/字符串/vtable/caller（写具体地址或文件:行号）
[conf]  E1|E2|E3            （§9）
[name-kind] rtti|tu|invented （名称依据）
[verified] 用什么手段验证过（反编译/单元测试/实机）
[todo]  待确认点
```

例（本项目实际用过的）：

```
[what] 继承人初始化；决定姓名与性别
[evidence] 日志 "InitNewHeir, %s, %u, %s, %d" @ heir.cpp:0x10D；
           调用 Random_GetGlobalMT(heir.cpp,0x127/0x142/0x14B/0x14D)
[conf] E1
[name-kind] tu
[verified] 反编译 + 桩单元测试（remainder 落在 [0,divisor)）
[todo] 条目 +36 标志的业务含义
```

### 8.2 行注释前缀（便于 grep）

`BUG:` 已确认缺陷 · `PATCH:` 与我方补丁相关 · `RTTI:` 类归属依据 ·
`GUARD:` 护栏/前置条件 · `NAME:` 命名理由 · `TODO:` 未定

### 8.3 语言

注释**用中文**（团队语言），但**标识符一律英文**。不要在标识符里混中文。

## 9. 证据等级与改名门槛

| 等级 | 判据 | 能否改名 |
|---|---|---|
| **E1** | 日志字符串含 `file.cpp:line`；RTTI/vtable 匹配；字符串或数据文件直接对应 | ✅ 可命名 |
| **E2** | 调用者/被调用者语义收敛；多处交叉引用一致；数据结构布局自洽 | ✅ 可命名（注释标 E2） |
| **E3** | 仅凭代码形态推测 | ❌ **只写注释，不改名** |

**门槛**：≥E2 才可改名。E3 的假设写进注释并加 `[conf] E3` + `TODO:`。

## 10. 重命名流程与台账

1. **先查重**：`entity_query` 确认新名未被占用。
2. **dry-run**：批量重命名先跑 `dry_run`。
3. **逐个验证**：用 `diff_before_after` 看改名后反编译是否更可读（尤其类型传播）。
4. **记台账**：追加到 `notes\rename-ledger.csv`：

   ```csv
   addr,old,new,evidence,conf,name_kind,date
   0x1414C7420,sub_1414C7420,Random_GetGlobalMT,"random.cpp:240 + 调用点",E1,tu,2026-10-02
   ```

5. **同步引用**：改名后 grep 旧名，更新 `notes\` 里的引用。
6. **补丁不受影响**：我方补丁按 **RVA + 签名**定位，不依赖函数名 —— 所以改名**不会**破坏补丁。
   这一点可以放心大胆地持续整理命名。

## 11. 禁止事项清单

1. 改 FLIRT / 第三方 / mangled 名（R2）。
2. 无 E2 证据就改名（R1）。
3. 无 vtable 证据就用 `Class::`（R3）。
4. 把地址、`sub_` 数字、日期写进名字。
5. 用 `_0`/`_1` 后缀区分不同函数。
6. 用 `Tag` 当类名。
7. 在标识符里用中文或空格。
8. 给两个不同函数起同名。
9. 用 `Get` 命名可能失败的函数。
10. 用 `Is`/`Has` 命名有副作用的函数。

### 12.3 `String*` 家族：能证实到什么程度

RTTI 已证实 **`CString`** 是**真实类名**（E1）。`StringAssign` / `StringAppend` / `StringFree` /
`StringAllocate` 很可能就是它的成员。

但**按 §5.2/§5.4，vtable 路线对游戏类不可用**，所以不能靠 vtable 一步到位。
可行的证据路径（§5.4 第 1 条）：

1. 这 4 个函数是否都对同一布局操作 —— `{ptr, size, cap}` + 16 字节 SSO？
   若是，则它们操作的是同一个类（E2）；
2. 它们的调用者是否都在操作 `CString` 对象；
3. 满足上述任一条 ⇒ 可升级为 `CString::Assign` 等；
   否则**保持现状**，仅在注释写 `[class-guess: CString]`（R3）。

## 14. 已决策（v2 定稿）

以下 6 项已由项目所有者决定，**作为本规范的强制条款**：

| # | 议题 | 决定 |
|---|---|---|
| 1 | `Class::Method` 的采用范围 | **分层采用**：仅当成员归属经 §5.4 严格证实（≥E2）时才用 `::`；其余一律用 `<模块>_<函数>`。**禁止"看起来像"就用 `::`。** |
| 2 | 模块标记分隔符 | **保持现状 `_`**。`::` 在 IDA 中有成员函数语义（§5.5），不得当作纯命名空间使用。 |
| 3 | 枚举成员风格 | **首字母大写（PascalCase）**，如 `GenderMale`；全库统一，不用 `GENDER_MALE`、不用 `Gender_Male`。 |
| 4 | 结构体成员前缀 | **无前缀**。如 `weight`、`genderFlag`（IDA 已限定所属结构体，前缀冗余）。 |
| 5 | 局部变量前缀 | **统一前缀**（§3.3）：`p`/`pp`/`n`/`i`/`k`/`b`/`f`/`s`/`v`/`fn`/`sz`。 |
| 6 | `Tag` 的地位 | 原稿中的 `Tag` **只是一个举例**，无特殊地位。类名一律以 §5.2 的 RTTI 实证表为准；`CCountry`/`CProvince`/`CCharacter` 不在 RTTI 中，故相关代码走 L2 模块标记。 |

## 15. 待补规范（你原稿未涉及、但本项目一定会遇到）

1. **脚本系统三层命名**：字符串键（snake_case）/ 关键字 ID / 实现函数（`Effect_`/`Trigger_`/`Command_`）。
2. **虚函数与 vtable 命名**（`??_7…@@6B@` 的风格与时机）。
3. **模板实例命名**（`std::vector<CPdxArray<…>>` 这种在 IDA 里几乎不可读时的退化规则）。
4. **存档/序列化字段的命名**（与 `settings.txt`、savegame 字段对齐，便于交叉验证）。
5. **多版本差异标注**（本作已停更，但 mod 会改数据；代码侧只有 1.37.5 一个版本，需明确"名称绑定到构建哈希"）。
6. **本地化键与 C++ 枚举的对应**（`MONARCH_*` 之类字符串 ↔ 枚举，需统一映射写法）。
7. **跨笔记引用格式**（`notes/x.md#L24` 还是 `函数名 @ 0xADDR`）—— 建议**以函数名为主、地址为辅**，
   因为改名会让地址式引用失效。
