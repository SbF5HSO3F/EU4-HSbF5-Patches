## 2. 分层架构

```
┌─ eu4.exe（游戏代码，我们只改站点处的 5~8 字节）─────────────────────┐
│  站点:  E9 rel32 ──────┐                                            │
└────────────────────────┼────────────────────────────────────────────┘
                         ▼
┌─ cave（我们自己分配，贴近 eu4.exe：base − 0x10000）─────────────────┐
│  FF 25 00000000 <8 字节绝对地址>   ← 14 字节，不受 ±2GB 限制         │
└────────────────────────┬────────────────────────────────────────────┘
                         ▼
┌─ stubs.asm 的 trampoline（在我们 DLL 里）──────────────────────────┐
│  MNP_ENTER:  pushfq + 16 个 push  ⇒ reg_pack（136 字节）            │
│              add qword ptr [rsp+18h], 70h   ← 修正 reg_pack::rsp    │
│              mov rcx, rsp / sub rsp, 20h                            │
│  call <handler>            ← ★ 业务逻辑全在 C++                      │
│  MNP_EXIT:   add rsp,20h / pop rdi,rsi,rbp / add rsp,8              │
│              pop rbx..r15 / popfq                                   │
│  <重放被覆盖的指令，通常 1~3 条>                                     │
│  push <resume> / ret                                                │
└────────────────────────┬────────────────────────────────────────────┘
                         ▼
┌─ C++ handler（monarchnamefix.cpp 的 mnp_h_p*）─────────────────────┐
│  业务逻辑；被覆盖指令的"数据部分"若能用 reg_pack 表达就一并做掉      │
└─────────────────────────────────────────────────────────────────────┘
```

**为什么必须两层跳转**：DLL 与 eu4.exe 相距 **26 GB**（实测 `delta=0x6C3E50000`），
`E8/E9 rel32` 都够不着；所以先用 5 字节 `E9` 跳到贴近 exe 的 cave，
再由 cave 写 14 字节绝对跳转。

**为什么用 `push <retAddr>; ret` 而不是 `E9 rel32` 收尾**：
回跳点因此可以是任意位置，不受"桩末尾必须是 5 字节 E9"的约束。

## 3. 九个站点（★ 本文最该被对照的部分）

**排列顺序 = 逻辑执行顺序，分三组。五处文件（`install.cpp` 的 `kSites[]`、
`stubs.asm` 的 trampoline、`monarchnamefix.cpp` 的 handler、`hookvars.cpp` 的变量、
`stubs.hpp` 的声明）**必须保持同一顺序**，由 `scripts/verify_site_order.py` 校验。

> **编号说明**：`P1..P11` 是【按添加时间】编的，**不是执行顺序** ——
> P4 是出口却编号在 P6 之前，P1/P2/P3 反而是最后补的。
> 编号保留不动（它在多份历史文档里被引用过，重编号会让旧笔记全部失准），
> 顺序靠本表的分组表达。

### 组 1：取模修复（名字选取阶段，最先执行）

| **P1** | `0x00DA989B` | 5 | `0x00DA98A0` | `mov rdi,r8` / `mov esi,edx` | **把随机值掩成 21 位非负数** |
| **P2** | `0x00280274` | 6 | `0x0028027A` | `mov eax,edi` / `cdq` / `idiv r8d` | **有符号除法 → 无符号** |
| **P3** | `0x00DA9A82` | 6 | `0x00DA9A88` | `mov eax,edx` / `cdq` / `idiv r8d` | **有符号除法 → 无符号** |

### 组 2：生成期姓名顺序（`BuildFullName_Impl` 内部，按执行时机）

| **P10** | `0x003142F2` | 5 | `0x003142F7` | `lea rcx,[rsp+30h]` | 追加姓之前：记下姓的字节数 |

| 站点 | RVA | 覆盖 | 回跳 | 被覆盖的原指令 | 我们做什么 |
|---|---|---|---|---|---|
| **P8** | `0x00A4B4A6` | 7 | `0x00A4B4AD` | `mov dword [rbp-50h],1` | `CMonarch_GetFullName` 重排 |

**定位方式**：字节模式（16~37 字节）+ **RVA 筛选**双判据。
模式负责"跨版本仍找得到"，RVA 负责"多个候选中确定是哪一个"
（P6 的序言在 `.text` 里有 **4 份完全相同的拷贝**，单靠模式永远不唯一）。

## 4. 三类修复各在做什么

### 4.1 取模缺陷（P1 / P2 / P3）—— "取第一号位的概率被放大"

三处的共同病根：**随机值/索引的高位为 1 时，有符号除法产生负余数**。

| 站点 | 缺陷形态 | 后果 | 修法 |
|---|---|---|---|
| **P1** | 随机源是 `Random_GetGlobalMT()` 的**完整 32 位**（可为负），`0xDA98C3` 直接拿 `edx` 做 `cdq; idiv ecx` | 负余数 ⇒ 取样全回落到第 0 号位 | 在这里 `and edx, 001FFFFFh` |
| **P2** | `mov eax,edi / cdq / idiv r8d` | 负余数被调用方按"越界"处理 | 掩高位 + 清 `edx` + `div r8d` |
| **P3** | 同上，源操作数是 `edx` | 负偏移直接算错地址（潜伏型 OOB） | 同上 |

**★ P1 的关键细节**：站点覆盖的两条指令是 `mov rdi,r8` 与 `mov esi,edx`。
掩码放在两条重放**之前**，`esi` 自然拿到同一个非负值
⇒ **不需要单独掩 `esi`**，两条路径（mode 0/2 用 `esi`、mode 1 用 `edx`）一起被覆盖。

**★ 分工原则**：
- **纯数据操作**（掩码、清零）→ C++ handler 改 `reg_pack`
- **除法指令**（`div r8d`）→ 留在桩里 —— `div` 的溢出行为
  （商放不下 32 位时抛 `#DE`）必须与硬件一致，用 C++ 的 `/` 表达不了

### 4.2 按文化决定姓名顺序（P6 / P7 / P10 / P11 / P4）

```
BuildFullName_Impl(out, sel, a3, a4)
  │
  ├─ [P6] 入口：从 a3+0x48 读文化名 → g_cult_name（每次调用都刷新）
  │
  ├─ [P7] 循环前：查配置决定该文化是否姓前 → g_sf_active
  │        ★ 只置标志，绝不碰 Src —— 此时 Src 还是空 SSO 串（cap=15），
  │          中文姓名按 3 字节/字编码，会直接撑爆
  │
  ├─   （原循环：逐段追加「段 + 空格」，首字符 # 的段跳过）
  │
  ├─ [P10] StringAppend 前：记下 r8 = 姓的字节数 → g_sur_len
  │
  ├─ [P11] StringAppend 后：用 g_sur_len 作边界，把「名 SP 姓」重排成「姓 sep 名」
  │
  └─ [P4] 出口：兜底 —— 若 P11 没生效，用 rax(out) + [r14+88h](文化) + [rbp+78h](姓) 再试
```

**「姓」在 `BuildFullName_Impl` 里有【两个来源】**，只在 `call StringAppend` 前汇合：
1. `[rbp+0x78]` 的王朝名（非空时用）
2. 否则从名字表里选一个

**这是 P10/P11 能在同一处收口的原因。**

### 4.3 统治者 / 继承人 / 配偶（P8）

挂在 `CMonarch_GetFullName`（`RVA 0xA4B2C0`）的 `StringAppend(out, " "+王朝名)` 刚返回处。

- 边界用**两个字段的 size** 判定（`nlen = *(CMonarch+0x38)`、`dlen = *(*(CMonarch+0x68)+0x18)`），
  **不猜空格、不找 `0xBF`**
- 统治者自己的文化：`*(CMonarch+0x60)` → 文化对象；文化名在 **文化对象 `+0x48`**

## 8. 新架构下的血泪教训（写下来给未来）

1. **`pop rsp` 不是"跳过 8 字节"** —— 它的语义是 `rsp = [rsp]`。
   用它恢复寄存器包会让 rsp 错位 104 字节，症状是**进游戏静默闪退**
   （栈被破坏后 `ret` 跳到非法处，游戏自己的异常处理也拿不到）。
   正解：`add rsp, 8`。

2. **`push rsp` 压的是【递减前】的值**（x86 特例）。
   所以 `reg_pack::rsp` 的修正量是 `(S+8) − (S−104) = 112`，不是 120。

3. **模式必须够长** —— 5~8 字节会命中上万次（`48 89 5C 24 08` 命中 15437 次），
   6 个钩子只装上 1 个，表现为"名字全乱"。现在都是 16~37 字节 + RVA 筛选。

4. **重写之前先对照本文第 3 节的站点清单。**
   2026-10-05 那次重写漏掉 P1/P2/P3，直接导致"取第一号位概率被放大"复发 ——
   而 `notes\继承人姓名子系统-调用链与未决事项.md` 早在两天前就把这三处写清楚了。

5. **机器能算的就别用眼睛看。** 栈平衡、模式唯一性都已脚本化；
   这类错误肉眼看不出来，而代价是一次实机闪退。
