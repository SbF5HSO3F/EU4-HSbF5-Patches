# 08 · 无符号逆向的命名规范与证据等级

> 面向：任何长期维护一份游戏 IDB / Ghidra 工程的逆向者。
> 目标二进制：`eu4.exe` v1.37.5.0（Inca），带完整 RTTI，**无游戏符号表**。
>
> **为什么需要一份"命名规范"**：命名不是洁癖。
> 一个错名字会**污染整个 IDB 的类型传播**，而且**改名之后很难分辨哪些是猜的**。
> `sub_` 至少不骗人；`CCountry::GetRuler()` 会让你一路错下去。

---

## 0. 三条铁律

| 编号 | 铁律 | 理由 |
|---|---|---|
| **R1** | **证据优先**：没有 ≥E2 证据就**不许改名**，保持 `sub_` 并把假设写进注释 | 一次误判会污染整个 IDB，且改名后很难分辨哪些是猜的 |
| **R2** | **不覆盖真名**：CRT / std / boost / SDL / Steam / EOS / TBB / Nakama / FreeImage / `unknown_libname_*` 一律不动 | 这些是 ground truth，改了就丢了唯一的库级信息 |
| **R3** | **不猜类归属**：用 `Class::Method` 之前必须验证 `this` 的 vtable 属于该类 | 类名错 = 语义错，**比 `sub_` 更有害** |

> **R1 是有代价得来的**：项目早期曾把"继承人随机姓名"的来源判成文化的 `male_names`，
> 实际是 `common/countries/*.txt` 的 `monarch_names` —— 当时只有 E3 级证据却当 E1 用了。
> **所以"证据等级"和"改名门槛"必须写进规范、写在注释里。**

---

## 1. 证据等级与改名门槛

| 等级 | 判据 | 能否改名 |
|---|---|---|
| **E1** | 日志字符串含 `file.cpp:line`；RTTI / vtable 匹配；字符串或数据文件直接对应 | ✅ 可命名 |
| **E2** | 调用者 / 被调用者语义收敛；多处交叉引用一致；数据结构布局自洽 | ✅ 可命名（注释标 E2） |
| **E3** | 仅凭代码形态推测 | ❌ **只写注释，不改名** |

**门槛**：**≥E2 才可改名**。E3 的假设写进注释并加 `[conf] E3` + `TODO:`。

> ★ **本项目台账统计**（`rename-ledger.csv`，176 行）：
> `E1` 115 行 · `E2` 59 行 · `E3` **2 行**。
> 按 `name_kind` 分：`invented` 124 · `absorbed`（吸收第三方）40 · `tu`（翻译单元）9 · `lib` 2 · `from-log` 1。
>
> **E3 只有 2 行**这件事本身说明规范被执行了 —— 如果没有门槛，这个数会大得多。

## 2. 类名与作用域（最容易做错的一层）

### 2.1 RTTI 能给什么、**不能**给什么（实测结论）

**能给：真实的类名拼写。**
从 `.rdata` / `.data` 提取 **507 个类型描述符**，剔除库类型后得到 **66 个类名 token**。
包含：

- 核心值类型：`CString`、`CFixedPoint`
- 脚本 / 触发器：`CRootTrigger`、`STokenModifierEffect`
- 应用与框架：`CEU4Application`、`CPdxArray`、`CPdxMeshObject`、`SPdxParallelFor`
- **外交动作整套**：`CWar`、`CAlliance`、`CRoyalMarriage`、`CMilitaryAccess`、`CSubsidies`、
  `CGuarantee`、`CDependency`、`CFleetAccess`、`CWarning`、`CImproveRelation` …
  —— 与数据目录 `common/diplomatic_actions`、`common/new_diplomatic_actions` **一一对应**
  ⇒ ★ **数据侧与代码侧互相印证的绝佳例子**
- 容器：`CRelationsContainerArray`（出现 22 次）、`CList`、`CBlob`、`CMessage`、`CModifier`

**不能：判定"某函数属于哪个类"。**

实测 507 个描述符里**只有 82 个**被 COL（Complete Object Locator）引用，
而这 **82 个全部是 MSVC 运行时内部** —— locale facets（`ctype` / `moneypunct` / `num_get`…）、
异常类（`exception` / `bad_alloc`…）、Concurrency 接口，以及 MSVC 自带 demangler 的内部节点类型。

**游戏类一个都没有**：`CString`、`CFixedPoint`、`CRootTrigger`、`CCustomCountryLoadTask`、
`CMultiStopMissionAndPerformAction` 的 COL 引用数**都是 0**。

⚠️ **所以"用 vtable 反查类归属"这条常见建议，对游戏类不成立。**

**还有一条关键事实**：**`CCountry`、`CProvince`、`CCharacter` 在 RTTI 中完全不存在。**
游戏里最重要的三个类拿不到真名 ⇒
国家 / 省份 / 角色相关代码的**正确出路是模块标记**，
这也正好说明 `Country_CreateNewHeir` 这类命名是**合规的，而不是"退而求其次"**。

### 2.2 ★★ 类名的第二权威来源：日志字符串（**比 RTTI 更有用**）

RTTI 只覆盖"被多态使用的类型"，而游戏类几乎**全部没有** RTTI 描述符。
但**日志 / 断言字符串里带着开发者亲手写的 `ClassName::MethodName`**：

```
CCountry::Clear() %s                                       @0x141C57E90
CCountry::SetCapital set _bUpdateSupplyRangeCache          @0x141C591A8
CCountry::GenerateNonHistoricalAttributes %s %d            @0x141C58198
CProvince::Conquer: %d, %s                                 @0x141CD8A20
CMonarch::SetAttachedLeader _LeaderID %i                   @0x141CDC848
CDefineRulerEffect::Execute %i                             @0x141CA69F8
CDefineHeirEffect::Execute %i                              @0x141CA6B20
CPapacyInstanceData::ChooseNewWeightedPope %i %d           @0x141D222B0
CCountryModifiers::EState::CALCULATING when called from …  @0x141CCC758
```

已全量提取 **82 个类 / 154 个 `Class::Method`**。

**用途与限制（务必分清）**：

| 它能证明 | 它**不能**证明 |
|---|---|
| 该类名 / 方法名的**真实拼写**（E1，开发者自己写的） | 哪个**地址**实现了它 —— 一条日志串可能来自任意调用方 |
| 方法名可直接复用，如 `SetCapital`、`AddOwnedProvince` | 该方法的参数与返回值 |

⇒ **绑定地址的方法**：查该字符串的交叉引用，落到哪个函数，
该函数即为该方法（或其调用者）。
拿到"**字符串地址 + 引用函数地址**"这一对之后，才可用 `ClassName::Method`（L1，≥E2）。

> ⚠️ **两个来源不得混用**：
> RTTI 类型描述符回答"哪些类型参与了多态"；
> 日志字符串回答"开发者把类叫什么"。**判断类名拼写时以后者为准。**

### 2.3 三层规则

| 层 | 条件 | 命名形式 | 实测可得性 |
|---|---|---|---|
| **L1** | RTTI 中有该类名，**且**能用 §2.4 的证据确认成员归属 | `CClassName::Method`（**必须用 RTTI 原拼写**） | 游戏类几乎不可得；仅 12 个类拥有自己的描述符 |
| **L2** | RTTI 无，但已知日志来源 `xxx.cpp:line` | `<Module>_Function` | ★ **主路径** |
| **L3** | 两者都无 | 保持 `sub_`，假设写入注释 | — |

**已实测的游戏类命名**（RTTI 里没有，但日志里有）：

```cpp
CCountry::Clear() %s
CCountry::SetCapital set _bUpdateSupplyRangeCache
CCountry::GenerateNonHistoricalAttributes %s %d
CProvince::Conquer: %d, %s
CMonarch::SetAttachedLeader _LeaderID %i
CCountryModifiers::EState::CALCULATING when called from …
```

### 2.4 没有 vtable 时，如何建立"成员归属"证据

**按证据强度排序**（都可支撑 L1 的 `::`，但要求 ≥E2）：

1. ★ **`this` 字段自洽** —— 函数读写的 `*(this + 0xNNNN)` 偏移已被另一函数确证属于类 X
   ⇒ 强烈指向同一类。**最实用的一条。**
2. **构造 / 析构配对** —— `ctor` 写入的字段与目标函数读取的字段一致。
3. **数据文件字段映射** —— `common/` 或存档字段名与结构偏移一一对应。
   （本项目已用此法确证 `monarch_names` 表头 `+16/+20/+24/+32/+48` 与 40 字节元素布局。）
4. **调用者收敛** —— 全部调用者都处于类 X 的上下文。
5. **`typeid` / `catch` 引用** —— 代码里 `lea` 指向某类型描述符，
   只能证明"提到过这个类"，**最弱**。

**在拿到第 1～4 条之一之前，不要使用 `::`（R3）。**

### 2.5 `::` 对 IDA 的语义影响（必须知道）

IDA 把 `A::B` 视为 **C++ 成员函数**，会据此推断 `this` 指针与调用约定。

x64 下 `this` 在 `rcx`，这在多数情况下**恰好正确**，是有利的；
但若把**自由函数**硬写成 `A::B`，IDA 会做出**错误的 `this` 推断**，
**后续类型传播会一路错下去**。

⇒ **所以 R3 不是洁癖，是技术必要。**

## 3. 函数名规范

### 3.1 动词前缀 —— 含**返回值契约**

原稿最容易漏的是"契约"。**契约比"意义"更重要，因为它可被检查。**

#### 取用类

| 前缀 | 契约 | 失败时 |
|---|---|---|
| `Get*` | **必须成功**、无副作用、无失败路径 | 不允许失败；若可能失败则改 `TryGet*` / `Find*` |
| `TryGet*` | 返回 bool，结果经出参返回 | 返回 0，出参不动 |
| `Find*` | 可能找不到，返回指针 / 索引 | 返回 `NULL` / 无效值 |
| `Resolve*` | 由**间接标识**（tag / id / 名字）解析出对象 | 返回 `NULL` |
| `Lookup*` | 查表命中，O(1) 语义 | 返回 `NULL` |
| `Peek*` | 只读窥视，不改状态、不消耗 | — |

> **修订示例**：`GetProvinceByID(id)` 用的是 `Get`，但"按 ID 查"本质是**可能失败的查找**
> ⇒ 应为 `FindProvinceByID` 或 **`ResolveProvinceByID`**
> （"由省份 ID 解析出 `CProvince` 对象"）。

#### 判定类（**必须返回 bool，必须无副作用**）

`Is*`（属性判断）、`Has*`（是否持有 / 含）、`Can*`（能力 / 权限判断）、
`Should*`（策略判断）、`Was*` / `Did*`（历史标志）。

#### 变更类

`Set*`（直接赋值）、`Add*` / `Remove*`（集合增删）、`Clear*`（清空）、
`Reset*`（复位到初值）、`Toggle*`（布尔翻转）、`Mark*`（打标志）、`Touch*`（使失效 / 标脏）。

#### 创建销毁类

`Create*`（生成一个游戏对象，通常有副作用并注册）、`Destroy*`、
`Alloc*` / `Free*`（裸内存）、`Clone*` / `Copy*`、
`Ensure*`（不存在则创建）、`Init*`（就地初始化已分配对象）、`Fini*`（与 `Init*` 配对）。

#### 流程与算法类

`Load*` / `Save*`、`Parse*`（脚本 / 文本解析）、`Serialize*`、`Build*`（组装复合对象）、
`Update*`（增量刷新）、`Tick*`（每帧 / 每日推进）、
**`Apply*`（有副作用地施加）**、**`Calc*`（纯计算，无副作用）**、
`Evaluate*`（求值脚本表达式）、`Validate*`（校验并报告）、`Dump*`（调试输出）。

> **修订示例**：`GetTaxInccomeForm(args)` 有三个问题：
> ① `Form` 是 `From` 的拼写错误；② `Inccome` 是 `Income` 的拼写错误；
> ③ `Get…From(args)` 语义太泛 —— 若是在算收入，应用计算动词。
> ⇒ `CalcTaxIncomeFromModifiers(pMods)` / `CalcTaxIncome(…)`。

#### ★ 选取与随机类（**本项目核心领域，通用规范里常缺**）

`Pick*`（从集合中选一个）、`Roll*`（掷随机数）、`Randomize*`、
`WeightedPick*`（按权重选）、`Select*`（按规则选而非随机）。

> 这组**不是装饰性的**。本项目修的那个缺陷正出在这里：
> `WeightedNameList_PickByRandomIndex` / `PickNameFromCultureLists` 的命名
> **恰好让缺陷读起来一目了然**。

#### 日志 / 回调类

`Log*` / `Trace*` / `Assert*` / `Report*`；
`On*` —— **仅**用于"被系统回调的钩子"（如 `OnDailyTick`），**不要当作普通动词**；
`Handle*` —— 用于处理外部消息 / 命令（如 `HandleDiplomaticAction`）。

#### 我方补丁相关（与游戏函数隔离）

`Patch_*`：指我方补丁引入 / 包装的函数，**永不用来命名游戏原生函数**。

### 3.2 介词与词序

**介词只出现在中间或结尾，不是前缀。**

```
<动词><对象>                      GetRuler
<动词><对象>By<键>                FindCharacterByID
<动词><对象>From<来源>            CalcTaxIncomeFromModifiers
<动词><对象>In<容器>              FindProvinceInRegion
<动词><对象>At<位置/时刻>          GetProvinceAt(index)
<动词><对象>With<工具/依据>        PickNameWithWeight
<动词><对象>To<目标>               ConvertReligionTo(rel)
```

**介词选用表**：`By` 键 / 依据；`From` 来源；`In` 容器 / 范围；`At` 位置 / 时刻；
`With` 手段；`For` 受益者 / 目的；`To` 目标；`Of` 所属（**尽量避免**，`GetXOfY` 多数应写成 `Y::GetX`）。

**何时不用介词** —— 只有一个候选来源时，介词是噪音：

| 啰嗦 | 更好 |
|---|---|
| `GetRulerFromCountry()` | `Country_GetRuler()` |
| `GetNameByIndex(i)` | `GetNameAt(i)` |

**判据**：只有当函数名**脱离原型后会产生歧义**（"从哪儿取？"）时才加介词。

**大小写**：介词在函数名中**首字母大写**（`From`、`By`、`In`）。
整名 PascalCase，**不用下划线分词**（下划线保留给模块标记与既定后缀）。

### 3.3 缩写与词汇

> **铁则：函数名与类名禁止缩写；局部变量鼓励缩写。**

**例外**：已是**既定专名**的缩写可用 —— `ID`、`AI`、`UI`、`HRE`、`GUI`、`DLC`、`MP`、`SP`。

**术语表**：

| 概念 | 函数名用 | 局部变量可用 |
|---|---|---|
| 国家（三字母标识） | `Tag`（数据）/ `Country`（对象） | `tag`, `pCountry` |
| 省份 | `Province` | `pProv`, `provID` |
| 角色（统治者 / 继承人 / 配偶 / 顾问的基类） | `Character` | `pChar` |
| 统治者 / 继承人 / 配偶 / 顾问 | `Ruler` / `Heir` / `Consort` / `Advisor` | `pRuler`, `pHeir` |
| 君主（含模板与实例两个概念） | `Monarch` | `pMonarch` |
| 王朝 | `Dynasty` | `pDyn` |
| 文化 / 文化组 | `Culture` / `CultureGroup` | `pCul`, `pCulGroup` |
| 宗教 | `Religion` | `pRel` |
| 阶层 / 理念 / 任务 / 决议 / 事件 | `Estate` / `Idea` / `Mission` / `Decision` / `Event` | `pEstate`… |
| 修正 / 触发器 / 效果 / 作用域 | `Modifier` / `Trigger` / `Effect` / `Scope` | `pMod`, `pTrig` |
| 贸易节点 / 贸易品 | `TradeNode` / `TradeGood` | `pNode`, `pGood` |
| 单位 / 陆军 / 海军 / 舰队 | `Unit` / `Army` / `Navy` / `Fleet` | `pUnit`… |

> ★ **`Tag` 与 `Country` 必须区分**：**`Tag` 是数据（3 字母标识 + 索引），`Country` 是对象。**
> 这也是 `Tag::GetRuler()` 这个写法的错误来源 —— `Tag` 不该做类名。

**局部变量前缀**：`p` 指针 · `pp` 二级指针 · `n`/`i`/`k` 整数与下标 · `b` 布尔 ·
`f` 浮点 · `s` 字符串 · `v` 值 · `fn` 函数指针 · `sz` 大小。

## 4. 大小写总表

| 实体 | 规范 | 例 |
|---|---|---|
| 函数 / 方法 | PascalCase | `ResolveRulingDynasty` |
| 类 / 结构体 / 枚举 | 游戏类用 **RTTI 原名**；自造辅助类型 PascalCase 无前缀 | `CString` / `NameEntry` |
| 枚举成员 | ★ **首字母大写（PascalCase）**，全库统一 | `GenderMale` |
| 全局变量 | `g_` + PascalCase | `g_pGameState` |
| 静态成员 | `s_` + PascalCase | `s_DynastyDatabase` |
| 结构体成员 | ★ **无前缀**，小写或 camelCase | `weight`, `genderFlag` |
| 局部变量 | 前缀 + camelCase | `pCountry`, `nIndex` |
| 宏 / 常量 | UPPER_SNAKE | `MAX_RULER_AGE` |
| ★ **脚本键** | ★ **原样 snake_case（ground truth）** | `monarch_names`, `define_heir` |
| 脚本实现函数 | `Effect_<CamelKey>` / `Trigger_<CamelKey>` / `Command_<CamelKey>` | `Trigger_HasProvinceModifier` |

> **脚本键为什么必须保持 snake_case**：它是数据文件里的字符串，是**唯一确定**的事实。
> 但**"字符串键"与"实现函数"要分开命名** ——
> `common/` 下每个 effect / trigger 都有一个 C++ 实现。

## 5. 模块标记（类未知时的退化形式）

当只有 `xxx.cpp:line` 这种日志证据（**这是 EU4 里最可靠的证据来源之一**），
用 **`<Module>_<Function>`**，`Module` = 源文件主名转 PascalCase。

| 日志来源 | 模块标记 |
|---|---|
| `country.cpp` | `Country_` |
| `heir.cpp` | `Heir_` |
| `random.cpp`（clausewitzlib） | `Random_` |
| `gamestate.cpp` / `persistent.cpp` | `GameState_` / `Persistent_` |
| `effectimplementation.cpp` | `EffectImpl_` |
| `tradenodedefinition.cpp` | `TradeNodeDef_` |
| `opinion_modifier.cpp` | `OpinionModifier_` |
| `bitmapfont.cpp` / `localize.cpp` | `BitmapFont_` / `Localize_` |

**这正好解释并保留了现有命名**：`Country_CreateNewHeir`、`Random_GetGlobalMT` 都符合本规则 ✓

**但反过来**：**没有日志证据时不要凭空发明模块名。**

## 6. 工具专用规则（IDA）

### 6.1 绝对不可改名

- CRT / 标准库（`Sprintf`、`Vsnprintf`、`InitializeCriticalSectionEx`、mangled 名等）
- 第三方：SDL、Steam（`SteamAPI_*`）、EOS、TBB、Nakama、FreeImage、boost、luabind
- `unknown_libname_*`、`j_*`（thunk）、`nullsub_*`
- 形如 `name_0` / `name_1` 的**重复名后缀**（IDA 自动加，**不要当成版本区分**）

### 6.2 名称字面规则

- 允许：`A-Z a-z 0-9 _ ::`
- **禁止**：空格、`.`、`$`、`?`、`@`
  （后三者会让 IDA 当 mangled 名解析）、开头 / 结尾下划线（保留给编译器与 CRT）
- **禁止把地址写进名字**
- 建议长度 ≤ 40 字符（含 `Class::` 前缀）
- **禁止重名**：不要给两个不同函数同名（会破坏 xref 与脚本检索）

### 6.3 局部变量 / 栈变量 / 结构体

- 反编译器生成的 `v1` / `a1` / `a2`：**只在确实理解后才改**；`this` 应显式改名
- 栈变量用前缀
- 结构体成员按**真实偏移顺序**命名；未知填充用 `padding_XX`
- 位域 / 标志位：成员名 + 注释写清位含义（如 `flags` + `/* bit0: isFemale */`）

### 6.4 类型与 vtable

- `vftable` 类名与 RTTI 一致：`??_7CString@@6B@`
- 自造结构体 PascalCase，并在类型注释里写**证据**（偏移来源、验证方式）

## 7. 注释规范（长期项目最关键的一节）

### 7.1 函数注释模板（可直接复制）

```
[what]      一句话说清做什么
[evidence]  证据：日志/字符串/vtable/caller（写具体地址或文件:行号）
[conf]      E1|E2|E3
[name-kind] rtti|tu|invented
[verified]  用什么手段验证过（反编译/单元测试/实机）
[todo]      待确认点
```

**实际用过的例子**：

```
[what] 继承人初始化；决定姓名与性别
[evidence] 日志 "InitNewHeir, %s, %u, %s, %d" @ heir.cpp:0x10D；
           调用 Random_GetGlobalMT(heir.cpp,0x127/0x142/0x14B/0x14D)
[conf] E1
[name-kind] tu
[verified] 反编译 + 桩单元测试（remainder 落在 [0,divisor)）
[todo] 条目 +36 标志的业务含义
```

### 7.2 行注释前缀（便于 `grep`）

| 前缀 | 含义 |
|---|---|
| `BUG:` | 已确认缺陷 |
| `PATCH:` | 与我方补丁相关 |
| `RTTI:` | 类归属依据 |
| `GUARD:` | 护栏 / 前置条件 |
| `NAME:` | 命名理由 |
| `TODO:` | 未定 |

### 7.3 语言

注释**用中文**（团队语言），但**标识符一律英文**。**不要在标识符里混中文。**

## 8. 重命名流程与台账

1. **先查重**：确认新名未被占用。
2. **dry-run**：批量重命名先跑 `dry_run`。
3. **逐个验证**：用工具看改名后反编译是否更可读（尤其类型传播）。
4. **记台账**：追加到 CSV：

   ```csv
   addr,old,new,evidence,conf,name_kind,date
   0x1414C7420,sub_1414C7420,Random_GetGlobalMT,"random.cpp:240 + 调用点",E1,tu,2026-10-02
   ```

5. **同步引用**：改名后 `grep` 旧名，更新笔记里的引用。
6. ★ **补丁不受影响** —— 补丁按 **RVA + 签名**定位，不依赖函数名
   ⇒ **改名不会破坏补丁**。这一点可以放心大胆地持续整理命名。

## 9. 禁止事项清单

1. 改 FLIRT / 第三方 / mangled 名（R2）。
2. 无 E2 证据就改名（R1）。
3. 无 vtable 证据就用 `Class::`（R3）。
4. 把地址、`sub_` 数字、日期写进名字。
5. 用 `_0` / `_1` 后缀区分不同函数。
6. 用 `Tag` 当类名。
7. 在标识符里用中文或空格。
8. 给两个不同函数起同名。
9. 用 `Get` 命名可能失败的函数。
10. 用 `Is` / `Has` 命名有副作用的函数。

---

## 10. 从这份规范里能带走的五条

1. **"没有符号表"不等于"只能靠猜"。** 日志字符串里藏着开发者写的 `Class::Method` —— 82 个类 / 154 个方法。
2. **"类名可得"不等于"类归属可得"。** RTTI 有名字，但 vtable 路线对游戏类**走不通**。
3. **`::` 有语义后果。** 写错会让 IDA 的类型传播一路错下去。
4. **证据等级要能被检查。** E1/E2/E3 的判据必须是"可指着某样东西说"的，不能是"我觉得"。
5. **改名不破坏补丁（按 RVA + 签名定位）** ⇒ 可以持续整理，不必一次做对。
